# Spec Delta

## Purpose

Безопасно импортировать подготовленный Markdown и изображения как новую заметку в явно выбранную базу IGoNotes, сохраняя пользовательские файлы и однозначный результат повторных запросов.

## ADDED Requirements

### Requirement: Explicit base-scoped creation
Импорт SHALL создавать новую непустую Markdown-заметку в явно указанной настроенной базе и существующей папке с актуальной ревизией назначения. Он SHALL не переключать активную базу и не использовать её как неявный fallback.

#### Scenario: Import to inactive base
- **WHEN** пользователь отправляет корректный материал в неактивную базу
- **THEN** заметка появляется в выбранной базе, а активная база и открытый текст редактора не меняются

#### Scenario: Missing or changed destination
- **WHEN** выбранная папка отсутствует либо ревизия назначения устарела
- **THEN** импорт не создаёт заметку и возвращает ошибку назначения
- **AND** не создаёт произвольные родительские папки

### Requirement: Index-visible note destinations
Импорт SHALL принимать назначение заметки только в корень базы или в папку, видимую в дереве. Любой компонент `parent`, начинающийся с `.`, либо равный `assets` без учёта регистра SHALL отклоняться с `400 clipper_invalid_request` до резервирования попытки и записи файлов. Это ограничение SHALL не запрещать серверу сохранять изображения в `assets/images/`.

#### Scenario: Manually supplied excluded destination
- **WHEN** клиент отправляет заметку в `assets/`, `.hidden/` либо их вложенные аналоги, в том числе `nested/ASSETS/images/`
- **THEN** импорт возвращает `400 clipper_invalid_request` без создания journal claim, временного файла или заметки

#### Scenario: Visible nested destination
- **WHEN** корректная новая заметка импортируется в обычную существующую вложенную папку активной базы
- **THEN** подтверждённая заметка появляется при следующем запросе дерева

### Requirement: Preserve existing files
Импорт SHALL никогда не перезаписывать существующие заметки или изображения. Совпадение нового имени заметки SHALL возвращать `409 note_conflict`, позволяя пользователю выбрать другое имя.

#### Scenario: Filename collision
- **WHEN** файл с выбранным именем существует либо создаётся конкурентно до публикации
- **THEN** существующий файл сохраняется побайтно, а импорт возвращает `409 note_conflict`

#### Scenario: Invalid path
- **WHEN** назначение содержит выход из корня, абсолютный путь, запрещённое имя, компонент `.git` или обход через символьную ссылку
- **THEN** сервер отклоняет импорт без записи за пределами допустимого назначения

### Requirement: Local image integrity
Успешный импорт SHALL сохранять все переданные изображения в `assets/images/` выбранной базы и формировать работоспособные относительные ссылки из папки заметки. Сервер SHALL проверять тип, размер и целостность вложений и не загружать URL источников самостоятельно.

#### Scenario: Nested destination
- **WHEN** заметка импортируется в `research/articles/` с несколькими изображениями
- **THEN** её Markdown ссылается на локальные изображения по корректным относительным путям и отображается в IGoNotes

#### Scenario: Invalid or oversized attachment
- **WHEN** вложение повреждено, имеет неподдерживаемый тип, не соответствует заявленному digest либо превышает лимит
- **THEN** сервер отклоняет запрос, не публикует заметку и возвращает конкретную ошибку

#### Scenario: Explicit external fallback
- **WHEN** пользователь подтвердил сохранение недоступных изображений внешними ссылками
- **THEN** импорт сохраняет доступные изображения локально, оставляет подтверждённые внешние ссылки и возвращает соответствующие предупреждения

### Requirement: Idempotent import result
Каждый импорт SHALL иметь устойчивый идентификатор и digest неизменяемого содержимого запроса. Повтор завершённого запроса SHALL возвращать прежний результат без повторной записи; тот же идентификатор с другим содержимым SHALL отклоняться с `409 clipper_request_changed`.

#### Scenario: Lost success response
- **WHEN** импорт завершился, ответ потерян, приложение перезапущено и расширение повторяет тот же запрос
- **THEN** сервер возвращает сохранённые базу, путь и ревизию, не создавая вторую заметку или набор изображений

#### Scenario: Concurrent duplicates
- **WHEN** два одинаковых запроса с одним идентификатором поступают одновременно
- **THEN** публикуется не более одной заметки и оба клиента могут получить один итоговый результат

#### Scenario: Payload changed under same identifier
- **WHEN** клиент повторно использует идентификатор с другим текстом, назначением или вложениями
- **THEN** сервер возвращает `409 clipper_request_changed` без изменения ранее созданного материала

### Requirement: Recoverable publication
Сервер SHALL подтверждать успех только после сохранения заметки, вложений и устойчивого результата импорта. После прерывания он SHALL восстановить однозначный результат, не удаляя и не перезаписывая файлы, изменённые пользователем вне импорта.

#### Scenario: Failure before publication
- **WHEN** ошибка записи возникает до публикации заметки
- **THEN** сервер не сообщает об успехе, сохраняет возможность восстановления и удаляет только принадлежащие этой попытке неизменённые временные данные

#### Scenario: Restart during publication
- **WHEN** приложение аварийно завершено между сохранением изображений, публикацией заметки и фиксацией результата
- **THEN** до новых импортов в это назначение сервер завершает либо безопасно отменяет операцию по журналу
- **AND** при неоднозначном внешнем изменении возвращает `409 clipper_recovery_required`, не создавая дубликат

### Requirement: Explicit recovery handoff
Локальные настройки IGoNotes SHALL показывать операции, требующие ручного восстановления, и позволять явно прекратить такую попытку без удаления файлов. Расширение SHALL сохранять черновик и предупреждать о возможной уже созданной заметке перед новой отправкой.

#### Scenario: Abandon ambiguous import
- **WHEN** пользователь после разбора файлов подтверждает прекращение операции со статусом recovery_required в настройках IGoNotes
- **THEN** файлы остаются неизменными, попытка получает окончательный отказ `clipper_import_abandoned` и не публикуется повторно под прежним ID
- **AND** блокировка новых импортов из-за этой операции снимается

### Requirement: Respect base lifecycle and Git conflicts
Импорт SHALL сериализоваться с изменением конфигурации базы и операциями Git, соблюдать блокировку конфликтного рабочего дерева и обновлять индекс активной базы до сообщения об успешном завершении.

#### Scenario: Pending conflict
- **WHEN** для выбранного корня ожидается разрешение Git-конфликта
- **THEN** новая публикация блокируется с `409 git_conflict_pending`, а черновик остаётся доступен для повтора

#### Scenario: Active base refresh
- **WHEN** импорт успешно завершён в активной базе
- **THEN** следующий запрос дерева включает новую заметку без ручного сканирования
- **AND** открытая редактируемая заметка не перезагружается принудительно

#### Scenario: Ordinary Git synchronization
- **WHEN** после импорта запускается обычная Git-синхронизация выбранной базы
- **THEN** новая заметка и изображения обрабатываются как обычные локальные файлы без специального обхода Git-механизмов
