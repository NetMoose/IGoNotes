# Руководство пользователя IGoNotes

IGoNotes запускает локальный сервер и открывает редактор Markdown-заметок в браузере.

Приложение использует Go 1.26+, Svelte 5, Vite 8, Tailwind CSS 4 и CodeMirror 6. Заметки хранятся как Markdown-файлы, метаданные — в SQLite. Git-синхронизация необязательна: локальными базами можно пользоваться без Git.

## Запуск приложения

Запустите установленный бинарник:

```bash
igonotes
```

Сервер слушает только локальный адрес `http://127.0.0.1:8080`, а браузер открывается автоматически. Если браузер не открылся, перейдите по этому адресу вручную.

Поддерживаемые флаги:

- `--config`: каталог конфигурации; по умолчанию используется `<os.UserConfigDir()>/igonotes`.
- `--port`: порт локального сервера; значение по умолчанию `8080`.
- `--base`: имя уже настроенной базы, которую нужно открыть при запуске.
- `--no-browser`: не открывать браузер автоматически.

Например:

```bash
igonotes --port 9000 --base work-notes --no-browser
```

## Запуск как пользовательский сервис Linux

В Linux IGoNotes можно установить как пользовательский сервис systemd. Команда создает юнит текущего пользователя в `$XDG_CONFIG_HOME/systemd/user/igonotes.service`, если `XDG_CONFIG_HOME` задана, иначе в `~/.config/systemd/user/igonotes.service`. Сервис запускается сразу и включается для следующих входов пользователя в систему или пользовательских сессий.

```bash
igonotes service install --port 9000 --config /path/to/config --base work-notes
```

Если параметры не указаны, используются обычные значения по умолчанию. Повторная установка обновляет юнит и перезапускает сервис. Сервис всегда добавляет `--no-browser` при запуске, поэтому обычная вкладка браузера автоматически не открывается.

Не редактируйте и не заменяйте `igonotes.service` одновременно с выполнением `igonotes service install` или `igonotes service uninstall`. Файловая блокировка координирует только параллельные вызовы IGoNotes; конкурентные изменения другими процессами того же пользователя или прямыми командами user-systemd не поддерживаются.

Юнит хранит абсолютный путь к текущему бинарнику, но не копирует его. Выберите для бинарника стабильный путь: перемещение или удаление файла нарушит `ExecStart`. После перемещения бинарника или изменения пути повторно выполните `igonotes service install` из нового расположения.

Для пользовательского сервиса не нужны `sudo`, права `root` или системный юнит. IGoNotes не включает user linger автоматически, поэтому запуск до входа пользователя в систему и работа после завершения его последней сессии не гарантируются.

Состояние сервиса и журнал можно проверить командами:

```bash
systemctl --user status igonotes.service
journalctl --user-unit igonotes.service
```

Чтобы использовать IGoNotes как Chromium PWA, сначала установите сервис на стабильном порту, затем откройте в Chromium точный loopback-адрес, например `http://127.0.0.1:9000`, и установите приложение средствами браузера. Origin PWA включает порт: после смены порта нужно открыть и установить новый origin. Команды `igonotes service` не устанавливают и не запускают Chromium PWA.

Удаление сервиса выполняется командой:

```bash
igonotes service uninstall
```

Она останавливает и отключает сервис, а затем удаляет пользовательский юнит с точным маркером управления IGoNotes. Бинарник, конфигурация, метаданные, базы и заметки не удаляются.

Команды `igonotes service` не поддерживаются в Windows и macOS. На этих платформах остаются доступны обычный запуск и флаг `--no-browser`.

## Настройка при первом запуске

При новой или пустой конфигурации появляется обязательный мастер. До его завершения редактор недоступен. Настройка состоит ровно из трех шагов:

1. Выберите создание новой базы или подключение существующей.
2. Укажите имя и каталог. Кнопка `Обзор` открывает системный выбор каталога; если он недоступен, путь можно ввести вручную.
3. Проверьте итоговый путь и завершите настройку.

В режиме создания выбранный каталог является родительским: новая база создается по пути `<directory>/<name>`. Родительский каталог должен существовать, а итоговый путь не должен быть занят.

В режиме подключения укажите точный путь к существующему каталогу. Мастер подключает его на месте и не перемещает и не изменяет его содержимое.

## Приватное служебное хранение и пути баз

Глобальная защита путей уже действует: база не может содержать каталог конфигурации, SQLite `~/.igonotes/metadata.db` с файлами `-wal`, `-shm`, `-journal` и super-journal, либо приватный каталог `~/.igonotes/clipper-staging/`. Весь каталог конфигурации (в том числе заданный через `--config`) и весь staging зарезервированы: база также не может находиться внутри них. Проверяются реальные пути с учётом символических ссылок и существующих предков ещё не созданных каталогов.

Штатная база `~/.igonotes/bases/default` разрешена. Подключать весь `~/.igonotes` как базу нельзя. Проверяются все базы, включая неактивные, при запуске и изменениях настроек; выбор другой базы через `--base` не обходит проверку. При отказе API возвращает `422 invalid_base_path`, не меняя конфигурацию и не создавая каталог новой базы.

Если старая конфигурация пересекается со служебным хранением, запуск завершится до открытия SQLite и индексации. Приложение не переносит и не удаляет файлы автоматически. Для исправления:

1. Остановите приложение и пользовательский сервис, если он установлен; сохраните резервную копию `config.json` и заметок.
2. Вручную отделите пользовательские заметки от служебных каталогов: выберите отдельный каталог базы, не включающий конфигурацию, SQLite или staging. Не переносите служебные файлы в базу.
3. Исправьте `bases[].path` у каждой несовместимой базы в `config.json` на фактический каталог заметок; сохраните корректный `current_base`. `base_dir` — только контейнер, проверяются именно пути `bases[].path`.
4. Если `--config` расположен внутри базы по умолчанию, выберите отдельный каталог конфигурации и обновите параметры запуска/установку сервиса. Перезапустите IGoNotes после ручного исправления.

Защита относится к lifecycle приложения; одновременная внешняя подмена каталогов или символических ссылок другими процессами не синхронизируется его блокировками. HTTP text import/status Web Clipper доступны; `~/.igonotes/clipper-staging/` постоянно зарезервирован для приватных временных запросов.

## Интерфейс

- Слева находится дерево папок и заметок с командами создания, переименования, удаления и обновления. Последняя кнопка в ряду над деревом — шестерёнка `Настройки`.
- Справа находится редактор CodeMirror с режимами редактирования и предварительного просмотра.
- Панель инструментов вставляет заголовки, списки, ссылки, таблицы, блоки кода и другое Markdown-форматирование.
- В верхней части редактора доступны индикатор сохранения и кнопка `Сохранить`.
- В строке состояния внизу отображается путь текущей базы.

### О программе

Откройте `Настройки` слева над деревом и выберите вкладку `О программе`. Здесь показаны название IGoNotes и версия запущенного приложения. Для локальной сборки без релизной версии отображается `Сборка разработки`.

## Редактирование заметок

Выберите заметку в дереве или создайте новую. Изменения автоматически сохраняются через 2 секунды после последнего ввода. Кнопка `Сохранить` выполняет сохранение немедленно.

Изображения можно добавить кнопкой панели инструментов, вставкой из буфера обмена или перетаскиванием. Загруженные файлы сохраняются в `assets/images/`; предпросмотр поддерживает обычные Markdown-ссылки и Obsidian-формат `![[image.png]]`.

### Конфликт изменений заметки

Окно `Конфликт изменений` появляется только в двух случаях: сохранение вернуло `409 note_changed` либо терминальный Git-статус содержит путь открытой заметки в `changed_paths`, а в редакторе есть несохраненные правки. IGoNotes не отслеживает произвольные изменения файловой системы. При входящих изменениях чистая заметка перечитывается автоматически, а удаленная чистая заметка закрывается. В окне показаны `Моя версия` и `Версия на диске`.

- `Загрузить версию с диска` явно отбрасывает несохраненный текст редактора и открывает актуальный файл; грязный редактор не заменяется автоматически входящими изменениями.
- `Оставить мою версию` требует отдельного действия `Подтвердить перезапись` и перезаписывает актуальный файл на диске.
- `Объединить вручную` открывает поле итогового текста; после редактирования нажмите `Сохранить объединение`.
- Если файл был удален на диске, доступна только команда `Закрыть заметку`: редактор закроется, а удаленный файл не будет создан заново автоматически.

Пока окно открыто, нельзя перейти к другой заметке, в настройки или переключить базу. Сначала выберите один из вариантов восстановления.

## Git-синхронизация

### Что нужно подготовить

Для опциональной двусторонней синхронизации установите системный Git 2.28 или новее. Для каждой базы используются один remote `origin` и одна выбранная ветка. У пользователя должны быть права чтения репозитория и отправки изменений в эту ветку, а также настроенная Git identity: `user.name` и `user.email` в пользовательском или локальном Git config.

Авторизацию настройте заранее вне IGoNotes: SSH-agent с доступным ключом, credential helper для HTTPS либо подходящий Git config. Она должна работать неинтерактивно в окружении процесса IGoNotes, в том числе пользовательского сервиса. Приложение не устанавливает Git, не хранит токены или SSH-ключи и не открывает интерактивные запросы пароля. Недоступная авторизация приводит к ошибке операции.

HTTP(S)-адреса с userinfo (логином, паролем или токеном), query-параметрами или fragment отклоняются. Не вставляйте токены в URL; используйте чистый адрес репозитория и внешний credential helper.

Git hooks создания коммитов (commit hooks) и настроенная подпись коммитов остаются активны. Их ошибка или требование интерактивного ввода может прервать операцию. Отправка изменений выполняется с `git push --no-verify`, поэтому локальный hook `pre-push` пропускается. При синхронизации коммитятся **все неигнорируемые файлы базы**, включая изображения и файлы не в формате Markdown; исключения задаются через `.gitignore`.

### Подключение: четыре шага

Откройте настройки шестеренкой, раздел `Git`, найдите карточку базы и нажмите `Настроить Git` или `Изменить настройки`.

1. **Репозиторий.** Введите URL и нажмите `Проверить репозиторий`. Проверка доступности обнаруживает удаленные ветки, не изменяя `.git`, refs, файлы, remote или конфигурацию базы.
2. **Ветка.** Выберите обнаруженную ветку. Для действительно пустого remote введите имя в поле `Новая ветка`. Пустота означает отсутствие всех объявленных refs: репозиторий с одними tags не считается пустым. После выбора выполняется повторная проверка; отсутствующую ветку непустого remote подключить нельзя.
3. **Расписание и коммиты.** Выберите `Только вручную` или `Автоматически`. Разрешены только интервалы **5, 15, 30 и 60 минут**, по умолчанию — **15 минут**. Задайте `Шаблон сообщения коммита` и проверьте предпросмотр.
4. **Подтверждение.** Проверьте URL, ветку, расписание и предупреждения. Если требуются изменения, явно подтвердите `Создать Git-репозиторий`, `Заменить origin`, `Создать ветку` или `Объединить несвязанные истории`. Добавление отсутствующего origin показывается отдельно, без отдельного флажка. Нажмите `Сохранить Git-настройки` и дождитесь итогового статуса: принятие операции не означает завершения подключения.

### Что происходит при первом подключении

IGoNotes может инициализировать `.git`, добавить или с подтверждением заменить origin, подготовить выбранную ветку и зафиксировать локальные файлы. Пустая локальная база может получить существующую удаленную историю; пустой remote — начальный локальный коммит. Когда история есть с обеих сторон, приложение сохраняет локальный снимок и объединяет его с удаленной веткой. Несвязанные истории либо история, связь которой проверка не смогла доказать, требуют подтверждения объединения; возможные конфликты разрешаются в интерфейсе.

Перед переключением или слиянием при наличии локального снимка, требующего защиты, создается резервная ссылка `refs/igonotes/backups/...`, сохраняющая этот коммит. Это локальный Git ref, а не отдельная копия каталога; автоматическая очистка таких ссылок не обещается. Уже существующие коммиты и история сохраняются, а не заменяются принудительной отправкой.

Если подключение завершилось ошибкой, прочитайте ее в карточке и проверьте актуальный статус и настройки: Git-настройки могли уже сохраниться до ошибки постановки операции в очередь. Исправьте причину и повторите подходящее действие по текущему состоянию базы.

### Ручная синхронизация и два устройства

В деталях индикатора Git нажмите `Синхронизировать Git`, а в карточке настроек — `Синхронизировать сейчас`. Перед ручным запросом интерфейс завершает ожидающие загрузки изображений и сохраняет текущую заметку. Ошибка сохранения блокирует запрос. Затем операция получает удаленные изменения, фиксирует локальные неигнорируемые изменения, выполняет обычное слияние и отправляет зафиксированный результат. При конфликте push не выполняется до явного разрешения.

Кнопка дерева `Обновить дерево (Синхронизировать с диском)` и `POST /api/sync` только сканируют файловую систему и обновляют метаданные дерева. Они не выполняют Git fetch, merge, commit или push; Git-синхронизация использует отдельный `/api/git/sync`.

Для работы на двух устройствах подключите отдельный локальный каталог на каждом к одному репозиторию и одной ветке. Синхронизируйте первое устройство после редактирования, затем второе — для получения изменений. Автосинхронизация может выполнять те же операции по расписанию, но одновременное изменение одного файла все равно может потребовать разрешения конфликта.

### Автосинхронизация, ошибки и возобновление

Автосинхронизация действует для всех настроенных баз, включая неактивные, пока приложение запущено. Следующий срок отсчитывается от последней попытки; операции выполняются последовательно. После запуска просроченные базы получают стартовые слоты с шагом пять секунд, а не все одновременно.

Первые четыре последовательные операционные ошибки допускают следующую попытку. Если подряд произошли **пять** таких ошибок, база получает статус `Приостановлено`, автоматические попытки прекращаются. Конфликт слияния и отказ валидации сами по себе не увеличивают этот счетчик. Удаление удаленной ветки или переписывание удаленной истории также могут немедленно приостановить синхронизацию. Пауза и счетчик сохраняются после перезапуска; восстановление сети само по себе не возобновляет работу.

При статусе `Ошибка` можно исправить причину и нажать обычную кнопку синхронизации. При паузе появляется `Git-синхронизация приостановлена` с причиной, счетчиком и временем последней попытки. Нажмите `Повторить и возобновить`: интерфейс сначала завершит загрузки и сохранит заметку, затем сбросит счетчик и поставит одну sync-операцию в очередь. Дождитесь результата; первая новая операционная ошибка начинает счетчик с 1. Кнопка `Открыть настройки Git` помогает исправить URL, ветку или режим. Обычная синхронизация паузу не снимает, а возобновление не обходит конфликт или необходимость переподключения.

### Как читать статус

| Надпись | Значение |
|:---|:---|
| `Git не настроен` | База работает локально без Git-интеграции приложения. |
| `Выполняется` | Подключение или синхронизация приняты в очередь либо выполняются. |
| `Синхронизировано` | Последняя операция успешна, сохраненный счетчик ahead равен нулю. |
| `Есть локальные изменения` | После успешной операции сохраненный ahead больше нуля. |
| `Ошибка` | Операция не удалась; после исправления причины возможна следующая попытка. |
| `Приостановлено` | Требуется явное возобновление. |
| `Конфликт` | Нужно разрешить конфликты или отменить слияние. |
| `Требуется переподключение` | Откройте Git-настройки и повторно подключите базу. |
| `Статус неизвестен` | Еще нет распознанного снимка статуса; дождитесь его обновления. |

В деталях `Впереди:` (`ahead`) — количество локальных коммитов сверх известной удаленной истории; `Позади:` (`behind`) — количество известных удаленных коммитов, которых нет локально. Также показаны этап и время последней успешной синхронизации. Это сохраненный снимок последней операции, а не непрерывный контроль remote или файлов: нулевые счетчики не доказывают отсутствие новых несохраненных правок или новых коммитов на другом устройстве.

### Разрешение конфликтов Git

В статусе `Конфликт` вместо обычного редактора открывается рабочая область `Конфликты Git`. Обычные изменения файлов этой базы и автосинхронизация блокируются. Выберите файл: `версия на этом устройстве` — локальная сторона слияния, `версия из репозитория` — полученная удаленная сторона. Приложение не выбирает победителя автоматически.

- **Текстовый конфликт:** `Оставить версию на этом устройстве`, `Оставить версию из репозитория` или `Объединить вручную` с редактированием итогового текста.
- **Бинарный конфликт:** выбрать одну сторону либо, если доступно, `Сохранить обе версии` в разные пути. Бинарные байты не объединяются текстовым редактором.
- **add/add:** обе стороны независимо создали файл в одном пути; выберите сторону, объедините текст либо сохраните обе версии в разные пути, если соответствующее действие доступно.
- **modify/delete:** одна сторона изменила файл, другая удалила. Доступны `Сохранить версию на этом устройстве` или `Сохранить версию из репозитория` для существующей стороны, ручное объединение текста либо `Удалить итоговый файл` с подтверждением.
- **rename/delete:** одна сторона переименовала файл, другая удалила исходный путь. Проверьте исходный и итоговый пути; сохраните существующую сторону, объедините текст или подтвердите удаление. Удаление относится ко всем путям этого логического конфликта.

Используйте только действия, показанные для выбранного конфликта: отсутствующую сторону нельзя выбрать как файл, а доступность ручного объединения или сохранения обеих версий зависит от снимка. При выборе обеих версий укажите разные свободные пути. Выбор стороны сохраняет ее исходные байты; ручное объединение сохраняет введенный итоговый текст.

Файлы можно разрешать по одному: частичные решения сохраняются в Git, а оставшиеся конфликты доступны после возврата или перезапуска. Когда неразрешенных файлов не осталось, нажмите `Завершить слияние` и дождитесь результата: создается merge commit, обновляется дерево и выполняется push. Ошибка отправки не означает, что разрешение нужно повторить или что merge commit исчез.

Чтобы отложить решение, выберите другую базу в левой панели и нажмите `Открыть базу`. Конфликт текущей базы остается незавершенным, ее автосинхронизация не продолжается; черновик конфликтной заметки сохраняется для возврата в текущей сессии. Несохраненный текст поля объединения не является долговечным разрешением — сначала сохраните решение файла.

Для отказа нажмите `Отменить слияние`, затем `Подтвердить отмену`. Неразрешенные изменения слияния отменяются, восстанавливается локальное состояние до слияния, включая заранее зафиксированные локальные изменения; push не выполняется. Исходные версии остаются в Git-истории, но несохраненный ручной результат не становится коммитом. После успешной отмены база приостановлена: для новой попытки используйте `Повторить и возобновить`.

### Ограничения

Не поддерживаются force-push, rebase, Git LFS, submodules, несколько remotes для одной базы, база как подкаталог monorepo и произвольный интервал автосинхронизации. Автоматического выбора решения конфликта и системных уведомлений нет.

## Настройки баз

Кнопка с шестеренкой открывает полноэкранные настройки. В разделе `Базы заметок` можно без перезапуска:

- создать новую базу или подключить существующий каталог;
- переименовать базу и изменить ее путь;
- переключить активную базу;
- забыть неактивную базу.

Изменение настроенного отображаемого имени или пути обновляет только конфигурацию. IGoNotes не перемещает каталог или файлы базы.

Перед переходом в настройки или переключением базы IGoNotes немедленно сохраняет текущую заметку и ожидающие загрузки. Если сохранение завершается ошибкой, переход блокируется, чтобы несохраненные изменения не потерялись.

Команда `Забыть` удаляет только запись базы из конфигурации и никогда не удаляет каталог или файлы. Нельзя забыть активную или единственную оставшуюся базу.

Настройки Git позволяют подключить репозиторий к базе и управлять синхронизацией без перезапуска.

`Отключить Git` с подтверждением очищает только Git-настройки приложения, статус и расписание. Выбор `Только вручную` отключает регулярные попытки, сохраняя подключение. Отключение Git и команда `Забыть` не удаляют `.git`, коммиты, refs, remote origin, каталог или пользовательские файлы и не удаляют удаленный репозиторий.

Смена пути в настройках не перемещает базу: перенесите каталог самостоятельно и укажите его новое расположение. Для настроенной Git-базы новый путь требует повторного подключения через Git-настройки (`Требуется переподключение`); прежнее расписание не переносится автоматически.

## Веб-клиппер: подключения браузера

Доступны установка Chromium-расширения через Load unpacked, захват **Article/Selection**, отдельный редактор локальных черновиков, ручная подготовка изображений, **Send/Check/точный retry** и восстановление после закрытия браузера/перезапуска сервера. Захват преобразует материал в Markdown без изменения страницы и автоматической подмены режима, сохраняет черновик в IndexedDB и открывает редактор. **Saved locally** подтверждает завершённую транзакцию; для захвата сервер и секрет не нужны. Чистая установка показывает пустой список до первого захвата. Оставшиеся задачи раздела 9 — расширенная приёмка, Chrome/platform/manual-permission проверки и CI/distribution, а не ещё недоступные runtime-функции. Native image permissions в существующих smoke были test-only pregranted; ручной PASS настоящих permission prompts не заявлен.

При ошибке открытия редактора можно открыть уже сохранённый ID без повторного захвата. При **Not saved** держите popup открытым до скачивания текущего материала: старые черновики не удаляются автоматически, но новый материал ещё не сохранён. Порядок действий и ограничения — ниже.

Серверная часть уже реализована: создание, просмотр и отзыв подключений в настройках, Bearer discovery API `/api/clipper/v1/info`, `/bases`, `/folders?base=...` и HTTP import/status `/api/clipper/v1/imports`, включая проверенные изображения и автоматическое локальное восстановление импорта при запуске. В настройках «Веб-клиппер» также доступен раздел «Незавершённые импорты». Канонический контракт — в [документации API](api.md#web-clipper-v1--discovery-и-http-import-доступны), локальный text-only запрос — в документации разработчика.

### Установка расширения из исходников и первая проверка

Первая поставка — локальная сборка и **Load unpacked**, без публикации в Chrome Web Store или готового release ZIP. Нужны локальный checkout репозитория и настольный Chrome/Chromium. В manifest объявлен минимум 120; фактически проверен Linux Chromium **154.0.8037.97**. Проверка совместимости с последним Chrome и платформами запланирована отдельно (9.2).

1. В корне репозитория проверьте **Node.js 24** до npm-команд:

   ```sh
   node --version
   npm --prefix extensions/webclipper ci
   npm --prefix extensions/webclipper run verify
   ```

   `verify` выполняет тесты и сборку. Расширение собирается независимо от основного `web/` и Go embed.
2. Откройте `chrome://extensions`, включите **Developer mode**, нажмите **Load unpacked** и выберите `extensions/webclipper/dist`, не корень репозитория и не `src`. Сохраняйте весь каталог, включая `LICENSES/` и `THIRD_PARTY_NOTICES.txt`.
3. Откройте исходную главную HTTP(S)-страницу. Для **Selection** заранее, **до открытия popup**, выделите в ней нужный диапазон с форматированием. Откройте popup расширения и явно нажмите **Article** или **Selection**. Это сразу преобразует материал в Markdown и создаёт локальный черновик, а не предпросмотр перед сохранением.
4. Расширение сохраняет черновик и пытается открыть отдельную вкладку редактора. Дождитесь **Saved locally**: транзакция IndexedDB завершена, popup можно закрыть без потери сохранённого черновика. При ошибке открытия нажмите **Open saved draft** для того же ID; через **Open draft editor** доступен список. Повторный захват в любом режиме создаёт новый черновик, а не повторяет открытие прежнего.
5. Проверьте **Title**, **Filename**, **Source URL**, **Captured at** (UTC) и **Markdown**. Кнопка **Save** сохраняет правки вручную, **Download Markdown** скачивает полную текущую заметку с метаданными, включая несохранённые правки, без файлов изображений. Правила сохранения описаны ниже.
6. Нажмите **Prepare images**, явно предоставьте доступ подходящим хостам; для повтора — **Retry images / grant access**. Дождитесь **Stored locally** для нужных изображений: это проверенные и записанные в IndexedDB Blob-байты. Для допустимого HTTP(S)-изображения, которое решено оставить внешним, отметьте отдельный **Keep external reference**, проверьте URL/причину и отдельно нажмите **Confirm external references**. Выбор без подтверждения не разблокирует отправку; подробные ограничения ниже.
7. **Перед созданием подключения для доставки** подготовьте совместимый Go-бинарник из **текущего checkout** либо другую сборку с заведомой поддержкой Web Clipper protocol v1 и UI подключений. Нельзя предполагать такую поддержку у уже установленного/опубликованного бинарника. Для воспроизводимого запуска при **Node.js 24 и Go 1.26+** выполните из корня репозитория:

   ```sh
   node --version
   go version
   make all
   ./builds/igonotes --port 9000
   ```

   Go-сборка не нужна для локального захвата/редактирования/подготовки изображений. Bare `igonotes --port 9000` используйте только для заведомо совместимого PATH-бинарника. Завершите мастер базы в запущенном приложении. Затем в **Настройки → Веб-клиппер** заполните **Название подключения**, нажмите **Создать подключение**, скопируйте одноразовый **Секрет подключения**. В редакторе расширения откройте **Connection settings**, задайте **Endpoint** `http://127.0.0.1:9000` и **Connection token**, нажмите **Save connection**, затем явно **Test connection**. Подробная настройка ниже.
8. Нажмите **Load destinations**, выберите **Destination base**, существующую **Destination folder**, явно `(root)` для корня, затем **Confirm destination** и **Send**. Проверяйте показанное назначение: первая/активная база не подставляется, папки не создаются автоматически.
9. Дождитесь **Import confirmed**: receipt с базой/путём, SHA-256 ревизией и предупреждениями. В IGoNotes выберите именно исходную целевую базу через **Настройки → Базы заметок**; при необходимости нажмите над деревом **Обновить дерево (Синхронизировать с диском)**. Backend не переключает активную базу. Send не делает Git push: используйте отдельно обычную ручную Git-синхронизацию или настроенный autosync.

Для локального захвата, редактирования, скачивания и подготовки изображений не нужны запущенный IGoNotes, секрет, настройки подключения или **Test connection**. Захват не обращается к backend, не читает секрет и не запрашивает изображения. Их URL первоначально сохраняются как pending-метаданные с `blob: null`. Редактор — обычное текстовое поле без автоматической загрузки изображений. Ручная отправка в IGoNotes доступна отдельной кнопкой **Send**; скачивание Markdown не включает изображения.

### Явная подготовка изображений

До отключения сети или закрытия исходной страницы нажмите **Prepare images** в редакторе. По текущему Markdown, включая несохранённые правки, запрашивается разрешение только для подходящих HTTP(S)-хостов, затем сохраняется текст и подготавливаются изображения. При ошибке сохранения текст остаётся в редакторе, загрузка не начинается. Поддерживаемые data-изображения сохраняются локально без сети и разрешения хоста. Захват, открытие редактора, набор текста и настройки подключения не запускают подготовку автоматически.

Запрос использует optional host permissions из manifest, но просит только конкретную **схему и точный хост**, не все сайты или поддомены. Chrome match patterns охватывают **все порты** выбранной схемы/хоста, не один порт URL. Отказ или неподдерживаемый платформой pattern показывается ошибкой без расширения доступа; это относится и к public IPv6 image hosts, не меняя IPv4/localhost-only endpoint сервера.

Получение изображений не использует cookies страницы, Cookie/Authorization или Bearer IGoNotes: `credentials: omit`, без referrer и без credentialed fallback. Cookie-protected/авторизованные картинки могут не загрузиться, даже если видны на исходной странице. **Ни один redirect не следуется**, включая same-host и CDN `302`: укажите прямой допустимый URL и явно предоставьте доступ его хосту либо подтвердите допустимую внешнюю ссылку. Браузер может показать redirect как общую `network` ошибку. `blob:`, canvas, unsafe schemes, URL с credentials, localhost и private/loopback IP literals не загружаются; доступ к внутреннему объекту страницы не восстанавливается. Это фильтр literal-адресов, **не защита от DNS rebinding**. Подготовка сканирует Markdown AST (inline/reference images), не обычные ссылки, код или raw HTML `<img>`. HTML-изображения не загружаются и не переписываются; даже «Images ready» не гарантирует автономность произвольного raw HTML в body.

В списке видны буквальный URL, MIME, размер в байтах и **Pending**, **Failed**, **Stored locally** или **External confirmed**. Счётчик локальных изображений обновляется только после завершения транзакции IndexedDB с проверенными байтами. Ошибки разрешений, HTTP, формата, лимитов и хранения остаются видимыми. **Retry images / grant access** явно повторяет подготовку текущих URL. Во время подготовки редактирование и переключение заблокированы; **Cancel image preparation** отменяет сеть и сохраняет уже записанные изображения. Повторное открытие читает локальный кэш без загрузки источников. Превью и миниатюры не загружаются.

Если подходящее HTTP(S)-изображение нужно оставить внешним, отдельно отметьте **Keep external reference**, проверьте список выбранных URL и причин и нажмите **Confirm external references**. Один чекбокс не является подтверждением. Неподтверждённые недоступные изображения блокируют готовность. Небезопасные/private/blob/неподдерживаемые data-источники нельзя разрешить как внешние: исправьте или удалите их, если локальное сохранение невозможно. Материал с внешними изображениями помечен **not fully offline / uses external images** и зависит от сети. Выбор изначально пустой; изменение Markdown/источника, повтор подготовки, переключение или перезагрузка требуют нового подтверждения. Правка только заголовка его не сбрасывает. Во время `sending`/`uncertain`/`pending` доступен только просмотр кэша. Подготовка — локальная операция; отправка выполняется отдельно.

Fallback допустим только для прошедших URL-политику HTTP(S)-источников: неподготовленных/неудачных, в том числе APNG/animated WebP на таком URL. Текущий UI также позволяет намеренно оставить внешним уже сохранённое HTTP(S)-изображение, например ради upload-бюджета. Поддерживаемые data-изображения нужно подготовить локально; неготовые data и другие неeligible источники требуют правки/удаления, а не выдуманного HTTP URL для обхода проверки. Подтверждение — точная пара URL/причина, хранится в памяти текущего компонента до создания immutable attempt, а не как постоянное согласие черновика. Смена lifecycle также сбрасывает локальный выбор. Внешние ссылки не делают материал полностью автономным: при рендеринге в другом приложении может понадобиться сеть.

### Ручная отправка и неопределённый результат

После сохранения подключения и подготовки изображений нажмите **Load destinations**: расширение явно запрашивает протокол и список баз. Выберите **Destination base**, затем существующую **Destination folder** (либо `(root)`), нажмите **Confirm destination** и только затем **Send**. Автовыбора первой/активной базы и папки нет. Назначение сохраняется в текущем черновике; перед новой попыткой заново проверяются протокол и revision/существование папки. Изменение назначения требует повторного явного подтверждения, без молчаливой подмены. Активная база редактора IGoNotes не переключается.

Во время Send текст блокируется сразу. Попытка с неизменными ID, manifest и изображениями сохраняется до POST. После совпадающего receipt расширение сохраняет результат и удаляет только принадлежащие этому черновику локальные строки. На экране остаются исторические база/путь и буквальные предупреждения внешних изображений. При offline до POST черновик остаётся; после возможной отправки timeout, 5xx, разрыв связи или некорректный receipt означают **uncertain**, не разрешение на новую публикацию. Редактирование, удаление и подготовка изображений такой попытки заблокированы также из другой вкладки.

**Check attempt** запрашивает только статус прежнего ID. **Check / retry exact attempt** сначала проверяет статус и лишь для неизвестного ID повторяет прежний payload с теми же ID, endpoint и revision. Неизвестный GET не доказывает отсутствие конкурентной публикации. Автоматической отправки при открытии/восстановлении сети/сохранении подключения нет. При отзыве токена откройте доступные **Connection settings**, сохраните новый действующий секрет для исходного адреса и проверьте ту же попытку. Другой endpoint не переносит её: требуется восстановить исходный адрес.

Подтверждённые окончательные ошибки payload, назначения и `note_conflict` сохраняют редактируемый черновик; исправьте его и явно подтвердите назначение для новой попытки с новым ID. Старый rejected ID не повторяется. Валидный GET-снимок `state: rejected`, в том числе с `internal_error`, подтверждает отказ журнала; одиночный сырой POST `500 internal_error` этого не доказывает и оставляет uncertain. После `clipper_import_abandoned` файлы могут уже существовать: проверьте назначение и возможный дубликат перед новой отправкой. Pending/recovery_required, auth/setup и Git-конфликт удерживают прежнюю попытку. `clipper_request_changed` — сохраняемый sticky-конфликт идентичности: вручную исследуйте исходную попытку/файлы в IGoNotes, не редактируйте frozen payload и не создавайте новый ID для обхода. Поздний ответ другой вкладки, включая успех/отказ/авторизацию, не снимает этот hold и не разрешает cleanup. При ошибке локального сохранения receipt/очистки используйте Check, сохраняя черновик: новая попытка не нужна.

После закрытия editor/worker/браузера повторное открытие только читает локальное состояние и проверяет кэш, без GET/POST или загрузки изображений. Подтверждённые **Stored locally** байты сохраняются независимо от незаконченных соседних загрузок; **Pending/Failed** требуют ручного **Prepare images**, которое повторно использует проверенный кэш без обращения к исходной странице. Прерванный `sending` показан как unresolved/interrupted, а не бесконечно выполняющийся: доступны ручные **Check attempt**, **Check / retry exact attempt**, **Download Markdown** исходного текста и **Connection settings**. Другая открытая вкладка может ещё выполнять операцию; восстановление не отбирает её полномочия и не снимает блокировку по времени. Неизвестные/повреждённые метаданные сохраняются без небезопасной очистки. Если точный совпадающий receipt уже сохранён локально, ручной Check завершает только локальную очистку без HTTP.

Смена endpoint блокирует и GET прежнего ID, и POST: восстановите исходный адрес (новый действующий токен допустим). После перезапуска IGoNotes новая попытка с устаревшей revision назначения требует заново Load → выбор базы/папки → Confirm; автоподмены revision или первой базы нет. Уже завершённый импорт с потерянным ответом проверяется вручную по прежнему ID либо точным replay и возвращает исторический receipt без нового подтверждения назначения и дубликатов. Гарантия относится к **Saved locally** тексту и **Stored locally** изображениям: принудительное закрытие может потерять несохранённые правки и незавершённые потоки, даже если предупреждение закрытия было обойдено.

Исключение для сети — уже сохранённый совпадающий `succeeded` receipt с незаконченной локальной cleanup: **Check attempt** проверяет его и очищает только локальные строки без HTTP и без подключения, даже если текущий endpoint другой. Это не переназначение исторического импорта. Физические Blob сохраняются до подтверждённого успеха и успешной атомарной cleanup. Доступность сервера сама по себе ничего не отправляет; неизвестный GET `400` не разрешает новый ID. Исправные cached bytes повторно используются без сети даже после закрытия исходной страницы или отзыва host permission. После browser restart уже закоммиченные ready-изображения остаются, остальные требуют ручного Prepare.

### Режимы захвата и ошибки извлечения

- **Article** пытается выделить статью через Readability на клоне документа. Это best-effort извлечение, без гарантии распознавания каждой пустой статьи. При неудаче: `Could not extract an article. You can select content and choose Selection.` Выделите нужный материал вручную, снова откройте popup и явно выберите **Selection**. Автоматического переключения режима, сохранения всего DOM страницы или fallback на извлечённый текст нет.
- **Selection** захватывает только выбранный диапазон главного документа, сохраняя поддерживаемое форматирование. Пустое, свёрнутое, состоящее только из пробелов или находящееся в другом frame выделение даёт `Select non-empty content in the main page, then try Selection again.` Выделение только изображения допустимо, если клонируемый диапазон действительно содержит элемент `img`. После удаления неподдерживаемого содержимого результат всё же может оказаться пустым: `No supported content remains after conversion. Select content and try again.` Ошибка безопасной конвертации предлагает меньший фрагмент; частичный черновик не сохраняется.
- Поддерживаются только главные HTML/XHTML-документы по HTTP(S), без credentials в URL. Нет извлечения PDF, iframe (включая cross-origin), screenshot, canvas или shadow DOM и обхода paywall. Для `chrome://`, `file://` и страниц расширений: `Only HTTP(S) pages without URL credentials can be captured.` Для доступного PDF/не-HTML документа: `PDF and non-HTML documents are not supported.` Если браузер запретил внедрение, в том числе в PDF viewer, возможна общая фиксированная ошибка `Could not capture the active page. Check page access and try again.` Режим не меняется, внутренние ошибки браузера не показываются.
- Если страница сменилась во время захвата: `The active page changed. Open the popup on the source page and try again.` Вернитесь к нужному источнику и повторите явный захват. HTML-подобный текст и примеры скриптов внутри кода остаются буквальным кодом, а реальные элементы script удаляются при конвертации.
- При quota/ошибке транзакции или лимите **50 черновиков** старые данные сохраняются без автоматического удаления. **Not saved** означает, что новый материал остался только в popup: **не закрывайте его, пока Download current Markdown не скачает файл**. При ошибке скачивания оставьте popup открытым и повторите скачивание. Пока материал не сохранён, кнопки захвата заблокированы. Файл содержит текущие метаданные как ровно три безопасно экранированных YAML-ключа `title`, `source`, `clipped_at` и Markdown body, без изображений. Через **Open draft editor** можно вручную удалить ненужные черновики; это не сохраняет неудавшийся захват. При превышении **5 MiB UTF-8 Markdown** материал также доступен для скачивания без обрезки, предлагается меньшее выделение. Сначала скачайте файл, затем заново откройте popup на источнике для нового захвата.

### Необязательная настройка и проверка подключения

Подключение отдельно от локального захвата и используется ручной отправкой. Английские надписи ниже относятся к расширению, русские — к приложению IGoNotes.

1. **До создания подключения** соберите Go-приложение из **текущего checkout** либо используйте сборку с заведомой поддержкой Web Clipper protocol v1 и UI подключений. Наличие ранее установленного/опубликованного бинарника само по себе не подтверждает совместимость. При **Node.js 24 и Go 1.26+** выполните из корня репозитория:

   ```sh
   node --version
   go version
   make all
   ./builds/igonotes --port 9000
   ```

   Завершите первичную настройку базы и оставьте приложение запущенным на том же компьютере. Адрес примера — `http://127.0.0.1:9000` (без `--port` используется 8080). Bare `igonotes --port 9000` допустим только для заведомо совместимого PATH-бинарника. Для локального захвата и подготовки изображений эти Go-сборка и настройка не требуются.
2. В приложении откройте **Настройки → Веб-клиппер**, заполните **Название подключения**, нажмите **Создать подключение** один раз и вручную скопируйте одноразовый **Секрет подключения**. Подробности и замена потерянного секрета — ниже.
3. Откройте popup расширения, нажмите **Open draft editor** и в отдельной вкладке редактора — **Connection settings**. Введите **Endpoint**, например `http://127.0.0.1:9000`, и секрет в поле **Connection token**. Не помещайте секрет в URL.
4. Нажмите **Save connection**: сообщение `Connection saved locally. Not tested.` означает локальное сохранение без сетевого запроса. Затем явно нажмите **Test connection**: выполняется `GET /api/clipper/v1/info` с текущими полями, даже ещё не сохранёнными. Успех — `Connected: protocol v1 is supported.` Проверяются discovery и протокол v1, не отправка страницы. Для несовместимого протокола требуется совместимое обновление приложения/расширения. При недоступности проверьте запущенное приложение и порт; при ошибке авторизации — действующий неотозванный секрет; мастер настройки должен быть завершён.
5. Перезагрузите или закройте/откройте вкладку редактора и снова откройте **Connection settings**: сохранённые адрес и секрет должны остаться. **Clear connection** удаляет только локальные настройки, не отзывает подключение на сервере и не удаляет черновики. Для отзыва используйте **Отозвать** в настройках приложения.

Endpoint принимает только HTTP с `127.0.0.1` или `localhost`, порт **1–65535** и корень (завершающий `/` допустим). HTTPS, удалённые хосты, credentials в адресе, непустой путь, query и fragment отклоняются. IPv6 не заявлен как поддерживаемый и отклоняется.

### Локальные черновики, обновление и удаление

Редактор позволяет открыть существующий черновик, изменить **Title**, **Filename** и **Markdown**, вручную сохранить кнопкой **Save** и скачать текущую полную заметку кнопкой **Download Markdown**. **Source URL** и **Captured at** показывают источник и время захвата UTC отдельно от body. Индикаторы **Unsaved changes**, **Saving…**, **Saved locally**, **Changes not saved** различают несохранённые правки, сохранение, завершённую транзакцию и ошибку. Выбор другого черновика или **Refresh drafts** сначала сохраняет ожидающие правки; ошибка блокирует переход и оставляет текст доступным для исправления, повтора и скачивания. Закрытие/перезагрузка браузера предупреждает о несохранённых правках, но принудительное закрытие может их потерять. Скачивание — полная текущая заметка с frontmatter, не экспорт всех черновиков и не автономный архив со всеми изображениями.

Заголовок и имя независимы: например, `Лес: наука 🌲.MD` первоначально предлагает `Лес_ наука 🌲.md`. Меняются только символы имени, не заголовок; имя нормализуется в NFC, ограничено 255 UTF-8 байтами вместе с `.md`, пустой заголовок даёт `clip.md`. Правка заголовка и сохранение не сбрасывают выбранное вручную имя. Предложение не гарантирует отсутствия коллизий: при отправке серверный `409 note_conflict` потребует другое имя. Скачивание использует текущее имя с безопасной обработкой только для браузерного файла, не меняя поле черновика.

Оба скачивания включают текущие, даже несохранённые, метаданные в начале: `title: "Лес: наука 🌲.MD"`, `source: "https://example.org/?q=1#section"`, `clipped_at: "2026-10-23T12:00:00Z"` между строками `---`, затем пустую строку и исходный Markdown body. Кавычки и переводы строк безопасно экранируются как данные YAML; заголовок, URL с query/fragment и время сохраняют значения. Body, включая собственные `---`, CRLF и отсутствие конечного перевода строки, не изменяется; frontmatter не записывается в body черновика. Изображения в скачивание не входят.

В IndexedDB body хранится отдельно от полей title/source/time. Редактор не вставляет готовый редактируемый YAML-шаблон в **Markdown**: frontmatter собирается для скачивания и полного Markdown отправки. При отправке меняются только управляемые Markdown image destinations (reference images могут стать inline), остальной body сохраняется; выбранное вручную имя не подменяется. Автоматические пути изображений ASCII, но имя заметки может содержать Unicode.

Черновики, изображения и попытки хранятся в **IndexedDB** этого расширения в текущем профиле браузера; endpoint/секрет — отдельно в доверенном **chrome.storage.local**, не в browser sync. Это не резервная копия и не синхронизация с IGoNotes. Удаление расширения, профиля или очистка хранилища могут привести к потере всех черновиков, изображений и настроек; возможно и вытеснение данных браузером. **Clear connection** сохраняет черновики и изображения.

Локальные пределы — **50 черновиков** и **250 MiB физических Blob-байтов** суммарно, плюс metadata/IndexedDB overhead; это не обещание доступной квоты браузера. Старые данные автоматически не вытесняются самим расширением. При ошибке сохраните доступный текущий Markdown и вручную удалите ненужные редактируемые черновики (**Delete draft**) либо освободите место; frozen attempt не удаляйте для обхода неопределённого исхода. Download не экспортирует весь список, изображения или журнал попыток. Автоматического backup профиля нет; отдельный согласованный backup сервера описан в [разделе резервного копирования](#резервная-копия-и-восстановление).

После пересборки нажмите **Reload** у расширения на `chrome://extensions` и заново откройте редактор. Для прежнего хранилища сохраняйте путь `dist` и профиль браузера. Изменение пути распакованной сборки/ID расширения или профиля может дать отдельное пустое хранилище и потребовать повторного ввода адреса/секрета; переноса прежних черновиков нет. До удаления установки/профиля скачайте нужный Markdown. Детали модулей и проверки — в `extensions/webclipper/README.md` репозитория.

Сервер проверяет и публикует вложения: статические PNG/JPEG/WebP и GIF, включая все кадры анимации; APNG, animated WebP и SVG/PDF не поддерживаются (415). Лимиты включительные: **5 MiB полного форматированного Markdown с YAML** в декодированных UTF-8 байтах, 10 MiB на изображение, 50 MiB суммарно, 100 уникальных assets, 64 MiB на всё wire-тело запроса с JSON escaping/MIME-обрамлением; 40000000 пикселей на изображение, GIF canvas и каждый кадр, не более 100 GIF-кадров и 200000000 пикселей суммарно по кадрам (`1 MiB = 1048576` байт). Превышение даёт 413. Client preflight не заменяет полную авторитетную валидацию сервера. Изображения сохраняются без перекодирования в ASCII-пути `assets/images/clip-<import_id>-<sha256>.<ext>` (`jpg` для JPEG), одинаковые bytes/формат внутри импорта — один файл. Существующие имена не перезаписываются (`409 note_conflict`). Markdown публикуется последним, с подготовленными клиентом ссылками относительно папки заметки; preview поддерживает вложенные `../../assets/images/...`. Обычная загрузка картинок из редактора не меняется.

### Пути изображений в preview

- Только явно начинающиеся с `./` или `../` локальные пути считаются от папки открытой заметки. Для `research/articles/note.md` ссылка `![клип](../../assets/images/clip.png)` указывает на `assets/images/clip.png`, а `![рядом](./same.png)` — на `research/articles/same.png`. Для заметки в корне `./same.png` указывает на `same.png`.
- Компоненты `.`/`..` нормализуются до запроса `/api/raw`. Выход выше корня, например `../../../escape.png` из `research/articles/note.md`, отклоняется: у картинки нет активного `src`. Поиск другого файла по существованию не выполняется.
- Для совместимости пути без начальных `./`/`../`, включая `assets/images/...` и `other/image.png`, остаются путями от корня базы. Wiki-ссылки `![[assets/images/image.png]]` также остаются base-root, даже если внутри wiki-ссылки есть `./`; они не становятся note-relative. Готовые `/api/raw?path=...`, внешние HTTP(S) и `data:image/...` не переписываются.
- Локальный адрес трактуется как путь файла: percent-кодирование декодируется один раз, затем весь путь кодируется одним query-параметром `path`. `%20` означает пробел, `%25` — буквальный `%`, `%2520` — буквальные символы `%20` в имени. Unicode допустим; `?`, `#` и `&` в локальном адресе — символы имени, а не query/fragment API. HTML entities в атрибутах изображений обрабатываются как символы, например `&amp;` как `&`. Некорректное percent-кодирование и опасные схемы (`javascript:`, `vbscript:`) не активируются.

Frontmatter в раскрываемом блоке свойств показывается буквально, включая `<`, `>`, `&` и кавычки в title/source; его текст не становится HTML. Это точечная защита frontmatter и обработка image paths, а не полная HTML-санитизация Markdown body.

### Если импорт требует ручного восстановления

При pending/recovery_required приватные копии изображений сохраняются вне баз вместе с журналом. Не удаляйте `~/.igonotes/clipper-staging/` для повторной отправки: локальное восстановление автоматически выполняется после локального Git recovery и до запуска Git-синхронизации, первичной индексации и HTTP. Ошибка не гарантирует отсутствие частично опубликованных файлов; используйте прежний ID и GET/точный replay. Восстановление только дозавершает доказуемо принадлежащую импорту публикацию, не удаляя опубликованные или изменённые пользователем файлы, в том числе уже сохранённые в Git. Неизвестное владение, потерянные источники, изменённый физический корень и Git-конфликт сохраняют попытку для ручного разбора. Статус `recovery_required` доступен через GET status и не препятствует запуску сервера и работе несвязанных баз, но блокирует новые импорты в затронутый корень. Ошибки БД или отмена восстановления прерывают запуск до HTTP. Успешный receipt не означает, что файл впоследствии не изменялся.

Не удаляйте и не редактируйте pending journal в `~/.igonotes/metadata.db`, чтобы снять блокировку. Если восстановление невозможно или вы решили прекратить попытку:

1. Откройте `Настройки → Веб-клиппер → Незавершённые импорты`, найдите ID и исходный относительный путь. Текущий каталог нужной базы проверьте в разделе `Базы заметок`.
2. Проверьте на диске заметку по этому пути, изображения `assets/images/clip-<import_id>-…` и возможные временные файлы. Сохраните нужные материалы отдельно; прекращение не исправляет содержимое и не удаляет возможный дубликат.
3. Для состояния «Требуется ручное восстановление» нажмите «Прекратить попытку» и подтвердите действие в окне. Для «Выполняется» это действие недоступно; обновляйте список/status прежнего ID.

В окне подтверждения доступны «Отмена» (также Escape) и «Подтвердить прекращение». До подтверждения запрос не отправляется. Операция не удаляет и не меняет ни файлы базы, ни приватные источники/журнал; она окончательно отклоняет старый ID с `clipper_import_abandoned`. После перезапуска этот ID также не создаст файлы заново. Для новой отправки нужны явное действие, новый ID и подходящее свободное имя; проверьте возможный дубликат.

После прекращения список обновляется. «Обновить импорты» и «Повторить загрузку импортов» выполняют только чтение; автоматической повторной отправки или прекращения нет. При ошибке запроса проверьте список/status вручную, прежде чем повторять действие. Блокировка снимается только для прекращённой записи: другие незавершённые импорты того же корня сохраняют её. Состояния Git и активная база не меняются; секрет расширения не даёт доступа к этим административным действиям.

### Выбор папки

Доступный discovery API предлагает корень базы (`""`) и существующие папки, видимые в дереве заметок, включая вложенные. Он исключает символьные ссылки, все папки с именем, начинающимся с `.`, и папки `assets` без учёта регистра вместе с их содержимым на любом уровне: например, `.hidden`, `ASSETS`, `nested/.cache/deep` и `nested/assets/x`.

При HTTP text import скрытую папку или `assets` нельзя выбрать и ручным запросом: такой `parent` получит `400 clipper_invalid_request` до создания заметки и записи операции в журнал, одинаково для активной и неактивной базы. Корень разрешён; отсутствующие папки автоматически не создаются. Ограничение относится к папке заметки, а не к её имени или хранилищу изображений `assets/images/`. Точный повтор ранее завершённого импорта возвращает сохранённый результат.

### Создание подключения

1. Запустите IGoNotes и завершите мастер первичной настройки.
2. Откройте `Настройки` → `Веб-клиппер` (вкладка перед `О программе`). Список показывает названия, состояние `Активно`/`Отозвано`, время создания и дату отзыва.
3. Введите `Название подключения`, например `Laptop`: от 1 до 128 символов, не только пробелы, без управляющих символов. Нажмите `Создать подключение`.
4. Выделите и скопируйте показанный `Секрет подключения` вручную в **Connection token** в **Connection settings** расширения, указав адрес IGoNotes в **Endpoint**. Секрет используется ручными discovery/Send/Check и HTTP import через API; захвату и подготовке изображений он не нужен.

Секрет выдаётся один раз. `Скрыть секрет`, уход из раздела, создание или отзыв подключения очищают его с экрана. Повторное открытие списка не раскрывает секрет. На сервере в SQLite хранится только его SHA-256 digest вместе с метаданными; в `config.json` секрет не сохраняется. Если секрет потерян, отзовите подключение и явно создайте новое: оно получит новый ID и новый секрет, а не восстановит старый.

Во время загрузки и операций отображается состояние ожидания. При ошибке списка используйте `Повторить загрузку` или `Обновить список`. Ошибка создания или потерянный ответ могут означать, что подключение уже создано, но секрет не получен. Сначала обновите список и отзовите лишнюю или нераспознанную запись; затем при необходимости явно создайте новое подключение. Автоматически повторять создание нельзя: каждое нажатие создаёт отдельное подключение.

### Адрес и границы токена

Адрес по умолчанию — `http://127.0.0.1:8080`. Например, запуск совместимой сборки из текущего checkout командой `./builds/igonotes --port 9000` меняет его на `http://127.0.0.1:9000`; этот же адрес и порт укажите в **Endpoint** расширения. Сервер должен быть запущен на том же компьютере; требования и команды сборки приведены в [настройке подключения](#необязательная-настройка-и-проверка-подключения).

`localhost` и `127.0.0.1` — разные хосты для same-origin проверки, даже если ведут на loopback. Origin включает схему, хост и порт: интерфейс, открытый на `http://localhost:9000`, не может обращаться к management API на `http://127.0.0.1:9000` как к своему origin. Используйте один точный адрес для интерфейса и его запросов.

Секрет предназначен только для ограниченного Bearer-доступа к Clipper v1: сведения о протоколе, имена баз/папок, text import и его статус.

Он не даёт доступа к обычному API заметок, конфигурации, Git или управлению подключениями и не обходит существующие same-origin/setup проверки. Это не авторизация удалённого доступа; не помещайте токен в URL или конфигурацию приложения.

### Отзыв

Нажмите `Отозвать` у активной записи. При ошибке прочитайте сообщение рядом с ней и обновите список, чтобы проверить результат. Отозванная запись остаётся в списке с датой первого отзыва; повторный отзыв через API не меняет эту дату. Старый секрет больше не проходит проверку подключения: discovery/import/status HTTP-запросы получают `401 clipper_unauthorized`. Импорт повторно проверяет секрет после загрузки запроса; отзыв после этой проверки не отменяет уже принятую публикацию. Для замены создайте новое подключение; старый секрет повторно не выдаётся. Контракт discovery и text import описан в документации API.

## Хранение данных

- Markdown-файлы остаются в каталогах баз, выбранных пользователем.
- Изображения базы хранятся в `<путь-базы>/assets/images/`.
- По умолчанию конфигурация хранится в `<os.UserConfigDir()>/igonotes/config.json`. В Linux это `$XDG_CONFIG_HOME/igonotes/config.json`, если переменная задана, иначе `~/.config/igonotes/config.json`. Флаг `--config <каталог>` переопределяет каталог, и файл хранится в `<каталог>/config.json`.
- Метаданные дерева хранятся в SQLite: `~/.igonotes/metadata.db`.
- Эта же SQLite хранит Git-состояния, подключения Web Clipper и приватный журнал импорта (точный Markdown, план, checkpoints и receipts). Собственные источники изображений незавершённых импортов находятся в `~/.igonotes/clipper-staging/owned-*/source-*`, отдельно от удаляемого после HTTP-запроса request staging. Заметки и опубликованные assets остаются вне этих приватных путей, в каталогах баз.

### Резервная копия и восстановление

Автоматического backup приложения нет. Перед обновлением сделайте согласованную копию данных:

1. Штатно остановите IGoNotes (`Ctrl+C` или `systemctl --user stop igonotes.service`) и дождитесь полного завершения процесса: HTTP-запросов, Git workers и закрытия SQLite. Закрытия вкладки браузера недостаточно. Пока копируете, приложение должно оставаться остановленным, а файлы баз не должны изменяться другими программами.
2. Скопируйте **фактический каталог конфигурации** целиком: заданный через `--config`, либо `<os.UserConfigDir()>/igonotes` (в Linux — `$XDG_CONFIG_HOME/igonotes` или `~/.config/igonotes`). `--config` не переносит SQLite и staging.
3. В ту же копию включите `~/.igonotes/metadata.db` и существующие файлы её SQLite sidecar family: `metadata.db-wal`, `metadata.db-shm`, `metadata.db-journal` и super-journal `metadata.db-mj*`, если они остались. Не отбрасывайте требуемые sidecars и не смешивайте их с другой копией БД. Сохраните также весь существующий `~/.igonotes/clipper-staging/`, особенно owned sources pending/recovery_required импортов.
4. Скопируйте **все** настроенные каталоги `bases[].path` из сохранённого `config.json`, включая неактивные базы, Markdown, `assets`, временные файлы и `.git`, если он есть. Эти пути могут находиться на других дисках и вне `~/.igonotes`; одной копии домашнего служебного каталога недостаточно. Все части должны относиться к одному остановленному состоянию.

Копирование только SQLite при работающем приложении не является такой резервной копией. Git remote и локальные backup refs также не заменяют её: в них нет конфигурации, приватного журнала и owned sources.

Для восстановления снова полностью остановите приложение и сначала сохраните отдельную копию текущих данных, чтобы не затереть новые заметки и изображения. Восстановите согласованный комплект конфигурации, SQLite с его sidecars, staging и всех баз из одного backup в исходные пути; не накладывайте старую БД на новые файлы или старые sidecars на другую БД. Частичное восстановление не делает публикацию атомарной.

Для автоматического продолжения незавершённого импорта нужны также прежние native filesystem identities корня, файлов и staging sources. Те же пути и даже побайтно идентичные скопированные файлы не гарантируют тех же identities: обычная копия или восстановление на другой файловой системе часто меняет их. IGoNotes намеренно оставляет такую попытку в ручном восстановлении, не присваивает файлы молча и не считает одного hash доказательством владения. После запуска проверьте «Незавершённые импорты» и файлы по инструкции выше; если дозавершение невозможно, используйте подтверждённое прекращение, а не удаление private journal/staging. Даже после terminal receipt авария до cleanup может оставить orphan staging; он сохраняется, автоматической рекурсивной очистки нет.

### Откат версии приложения

Web Clipper добавляет миграцию SQLite **v5**. Бинарники с поддержкой только прежней схемы отклоняют более новую историю миграций; автоматической downmigration нет. Для отката нужен согласованный backup **до обновления** и соответствующий ему старый бинарник. Сначала сохраните отдельную копию всего текущего состояния, включая новые файлы, затем при остановленном приложении восстановите полный pre-upgrade комплект по правилам выше. Не исправляйте номера миграций и не удаляйте Clipper-таблицы вручную. Новая работа после backup остаётся в сохранённой текущей копии и не появляется автоматически в старом состоянии.

SQLite backup содержит digests подключений и даты отзывов, а не открытые секреты. Восстановление старого backup возвращает и прежнее состояние отзывов: подключение, отозванное позже даты backup, может снова оказаться активным.

## Завершение работы

При обычном запуске в терминале нажмите `Ctrl+C`, чтобы остановить локальный сервер.

Пользовательский systemd-сервис не останавливается при закрытии терминала. Для временной остановки выполните `systemctl --user stop igonotes.service`, а для постоянного отключения и удаления — `igonotes service uninstall`.
