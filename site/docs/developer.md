# Руководство разработчика IGoNotes

Добро пожаловать в команду разработчиков IGoNotes! Этот документ поможет вам начать работу с кодовой базой.

## Структура проекта

- `cmd/api/main.go` — точка входа приложения.
- `internal/service/` — бизнес-логика.
- `internal/repository/` — работа с BoltDB и файловой системой.
- `internal/model/` — структуры данных (Note, Node и т.д.).
- `web/` — статические файлы и шаблоны.

## Зависимости

- **Go 1.21+**
- **BoltDB** — встраиваемая БД для метаданных.
- **marked.js** — клиентский парсер Markdown.

## Запуск и сборка

```bash
# Установка зависимостей
go mod tidy

# Запуск сервера
go run ./cmd/api

# Сборка бинарника
go build -o igonotes ./cmd/api
```

## Работа с Git

Мы используем ветвевую модель:

- `develop` — основная ветка разработки.
- `master` — стабильная версия.
- `pages` — ветка для документации (Jekyll).

### Правила внесения изменений:

1. Создайте фича-ветку:
   ```bash
   git checkout -b feature/note-search
   ```
2. Вносите изменения, тестируйте.
3. Сделайте коммит:
   ```bash
   git add .
   git commit -m "Добавлен поиск заметок"
   ```
4. Отправьте в удалённый репозиторий:
   ```bash
   git push origin feature/note-search
   ```
5. Создайте Pull Request в `develop`.

## API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/notes` | Получение дерева заметок |
| GET | `/api/note?path=...` | Получение содержимого заметки |
| POST | `/api/save` | Сохранение заметки |

## Добавление новой функции

1. Создайте ветку.
2. Реализуйте модель и репозиторий.
3. Добавьте метод в сервис.
4. Обновите маршрутизацию в `main.go`.
5. Добавьте обработчик в `app.js`.
6. Проверьте стили в `style.css`.
7. Напишите документацию.
8. Сделайте PR.

## Документация

- `docs/user.md` — для пользователей.
- `docs/developer.md` — для разработчиков.
- `docs/api.md` — спецификация API.

Релизы публикуются через GitHub Actions при отправке тегов вида `v*` из стабильной ветки `master`.

---

> **Важно**: Все изменения в `master` и `pages` происходят только через слияние из `develop` после тестирования.
