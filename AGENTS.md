# IGoNotes — Редактор заметок на Go и Markdown

IGoNotes — это CLI-приложение на Go, которое при запуске поднимает локальный REST-сервер и открывает им же в браузере страничку веб-интерфейс для редактирования и сохранения Markdown-заметок. Проект поддерживает древовидную структуру каталогов (за хранение отвечает бэкенд), редактирование и предварительный просмотр Markdown-заметок с поддержкой современных спецификаций Markdown. Frontend реализован как одностраничное приложение (SPA) на Svelte, которое встраивается в бинарник и отдаётся сервером.

## Технологии

- **Бэкенд**: Go (1.26+) (маршрутизация `net/http`)
- **Фронтенд**: Svelte 5, Vite, **CodeMirror 6**, **marked.js**, **Tailwind CSS v4**
- **База данных**: SQLite (`modernc.org/sqlite`, чистый Go)
- **Git-синхронизация**: системный Git 2.28+ через `internal/git`, без `go-git`; необязателен для локальных баз

## Фронтенд: сборка и внедрение

- Фронтенд разрабатывается и собирается с помощью **Vite** в каталог `web/dist/`
- Сборка выполняется перед компиляцией Go с помощью `make all`
- Контент из `web/dist/` внедряется в бинарник через `//go:embed all:dist`

Рекомендуемая команда полной сборки:
```bash
make all
```

`make all` выполняет `npm --prefix web ci`, сборку frontend и `go build -trimpath` для `./cmd/api`; зависимости frontend устанавливаются по lockfile. Требуется Node.js 24.

Перед merge выполните из корня проекта:
```bash
npm --prefix web run verify
make test
make test-git
make test-race
make vet
make verify
```

`make test-git` требует native Git 2.28+ и устанавливает `IGONOTES_REQUIRE_GIT_INTEGRATION=1`; обычные Go-тесты допускают пропуск Git integration при недоступном или старом Git. Интеграционные тесты используют временные локальные bare remotes, без внешней сети.

## Структура данных

```text
<configured base root>/
├── note.md
├── nested/
│   └── another-note.md
└── assets/
    └── images/
        └── Paste image 20260714150000.png

<os.UserConfigDir()>/
└── igonotes/
    └── config.json
```

- Конфигурация приложения по умолчанию: `<os.UserConfigDir()>/igonotes/config.json`; флаг `--config` переопределяет каталог конфигурации
- В Linux каталог конфигурации приложения — `$XDG_CONFIG_HOME/igonotes`, если `XDG_CONFIG_HOME` задана; иначе `~/.config/igonotes`
- SQLite с метаданными: `~/.igonotes/metadata.db`

## REST API

| Метод | Путь | Описание |
|:---|:---|:--- |
| GET | `/api/notes` | Получить дерево заметок (JSON) |
| POST | `/api/notes` | Создать заметку или папку |
| GET | `/api/note?id=...` | Получить JSON с `content` и `revision` |
| DELETE | `/api/note?id=...` | Удалить заметку или папку |
| POST | `/api/save` | Сохранить с `expected_revision`, получить новую `revision`; `409 note_changed` без перезаписи при несовпадении |
| PUT | `/api/rename` | Переименовать файл или папку |
| POST | `/api/sync` | Принудительно синхронизировать ФС и БД |
| GET | `/api/info` | Получить системную информацию (путь к базе) |
| GET | `/api/raw?path=...` | Получить статический файл/картинку из базы |
| POST | `/api/assets` | Загрузить изображение |
| GET/PUT | `/api/config` | Получить/сохранить настройки |
| POST | `/api/setup` | Завершить первичную настройку с первой базой |
| POST/PUT/DELETE | `/api/bases` | Добавить, изменить или забыть базу |
| POST | `/api/bases/switch` | Переключить активную базу |
| POST | `/api/system/select-directory` | Открыть системный выбор каталога |
| POST | `/api/git/probe` | Проверить локальный/удаленный репозиторий без изменений |
| PUT/DELETE | `/api/git/config?base=...` | Сохранить Git-настройки и поставить initialize в очередь / отключить Git |
| GET | `/api/git/status?base=...` | Статус одной базы, без `base` — всех баз |
| POST | `/api/git/sync?base=...` | Поставить ручной sync в очередь |
| POST | `/api/git/resume?base=...` | Снять паузу и поставить sync в очередь |
| GET | `/api/git/conflicts?base=...` | Получить снимок конфликтов |
| PUT | `/api/git/conflicts/resolve` | Разрешить один конфликт |
| POST | `/api/git/conflicts/complete?base=...` | Поставить завершение слияния в очередь |
| POST | `/api/git/conflicts/abort?base=...` | Поставить отмену слияния в очередь и приостановить sync |

Git-операции отвечают `202` при принятии в очередь, не при завершении. Текущие состояния баз: `unconfigured`, `initializing`, `ready`, `syncing`, `error`, `paused`, `conflict`, `needs_reconnect`. Терминальный статус содержит `changed_paths`; обычный sync не снимает паузу. После пяти последовательных операционных ошибок требуется явный resume. Контракты запросов и машинные коды ошибок: `docs/api.md`.

## CLI-флаги
- `--config` — каталог конфигурации (по умолчанию `<os.UserConfigDir()>/igonotes`)
- `--port` — порт сервера (по умолчанию `8080`)
- `--base` — имя базы для открытия
- `--no-browser` — не открывать браузер автоматически

Для уже настроенной базы `work-notes`:
```bash
igonotes --port 9000 --base work-notes
```

## Текущее состояние (что уже сделано)
Проект успешно инициализирован, фронтенд и бэкенд полностью интегрированы:
- **Запуск приложения**: Реализовано автоматическое кроссплатформенное (Windows, macOS, Linux) открытие локального URL в браузере при старте, отключаемое ключом `--no-browser`.
- **Дерево и ФС**: Приложение успешно сканирует папку базы и строит иерархическое дерево через SQLite. Реализовано "умное" ожидание фоновой синхронизации: при старте бэкенд блокирует запрос дерева до окончания индексации, благодаря чему фронтенд всегда получает полные данные. Добавлена кнопка обновления дерева, которая через `POST /api/sync` мгновенно синхронизирует изменения с диска.
- **Интерфейс**: Сверстан общий Layout (разделенный на дерево и редактор) на Tailwind CSS. Добавлен глобальный статус-бар на всю ширину окна внизу экрана для отображения текущего пути к базе заметок. Кнопки управления в дереве заметок оформлены в виде иконок с всплывающими подсказками.
- **Редактор**: CodeMirror 6 с поддержкой Markdown. Реализовано живое превью с интерактивными чекбоксами задач (AST-парсинг), поддержкой YAML Frontmatter (аккуратно скрывается в `<details>`). Добавлена панель инструментов с иконками для форматирования текста (вкл. таблицы с интерактивной сеткой, списки, подчеркивание). Реализованы выпадающие списки для уровней заголовков и вставки блоков кода. Добавлено автодополнение Markdown-команд через `/` и `\`, а также автозакрытие скобок.
- **Подсветка синтаксиса**: Динамическая подсветка блоков кода работает прямо в редакторе (через `@codemirror/language-data`) и в режиме превью (через `highlight.js` с темной темой).
- **Автосохранение**: Работает надежное debounce-сохранение (2 секунды) без перезагрузки интерфейса.
- **Управление**: Полноценные модальные окна (Tailwind UI + requestAnimationFrame автофокус) для создания, удаления и переименования файлов и папок с защитой от конфликтов имён (`409 Conflict`). Добавлено умное модальное окно вставки ссылок с автозаполнением выделенного текста.
- **Медиа и файлы**: Поддерживается загрузка картинок (через Drag&Drop, Paste из буфера обмена или кнопку) с генерацией безопасных имен (с timestamp). Настроена защита от Path Traversal при отдаче статики. Работают Obsidian-стиль ссылки вида `![[image.png]]`.
- **Настройки баз**: Полноэкранный раздел позволяет создавать и подключать базы, переименовывать их, менять путь, забывать и переключать без перезапуска. Перед открытием настроек и переключением приложение немедленно и безопасно сохраняет текущую заметку; ошибка сохранения блокирует переход. Команда «Забыть» удаляет только запись из конфигурации и никогда не удаляет каталог или файлы.
- **Git**: Работают подключение с probe и подтверждениями, последовательный FIFO worker с долговечной очередью/статусами в SQLite, autosync всех настроенных баз, явное разрешение конфликтов и локальное восстановление после перезапуска. Конфликты блокируют обычные изменения базы до resolve/complete/abort. Shutdown отменяет текущую операцию без заключительного commit/push.
- **Ревизии заметок**: GET/save возвращают `revision`, клиент сохраняет с `expected_revision`; `409 note_changed` требует перечитать диск и явно подтвердить восстановление. Входящие `changed_paths` перезагружают чистую заметку либо открывают stale recovery для грязной.
- **Архитектура Git**: `CommandRunner` запускает executable + argv без shell; nil stdin дает EOF, всегда `GIT_TERMINAL_PROMPT=0`. `internal/git/Service` выполняет одну операцию репозитория; `GitManager` владеет worker/очередью/статусами/расписанием; `SettingsService` владеет Git-конфигурацией. Lock order: `coordinator -> SettingsService.mu -> NoteService.baseMu -> repository/SQLite`. Fetch идет до note write lock, push — после reindex/unlock. SQLite и конфигурация находятся вне баз. Commit hooks активны; `git push --no-verify` пропускает `pre-push`. Подробности платформенного runner и CI: `docs/developer.md`.
