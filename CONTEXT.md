# IGoNotes — Редактор заметок на Go и Markdown

IGoNotes — это будет CLI-приложение на Go, которое при запуске поднимает локальный REST-сервер и открывает им же в браузере страничку веб-интерфейс для редактирования и сохранения Markdown-заметок. Проект должен поддерживать древовидную структуру каталогов за хранение которой отвечает бэкенд, редактирование и предварительный просмотр Markdown-заметок с поддержкой современных спецификаций Markdown, за это отвечает одностраничное приложение-страница на HTML+JS, которая открывается в браузере бэкендом и отдаётся как статический контекст.

## Особенности

- REST-сервер на Go
- При первом запуске нужна процедура настройки параметров и хранилища, возможно мастером, в веб-интерфейсе, там же предусмотреть возможность открытия уже имеющейся базы настроек
- REST-сервер при запуске должен поддерживать ключи командной строки, для передачи параметров запуска (где искать настройки как минимум), но они должны быть необязательны
- Настройки программы должны храниться в стандартном `~/.config` для Linux и таких же стандартных местах для Windows и macOS
- Сборку бинарника осуществлять для linux 386, amd64, windows 386, amd64, macos 386, amd64, arm64
- Хотелось бы использовать для сборки релиза возможности gitverse.ru (сборка как в Gitea)
- Веб-интерфейс с редактором Markdown и просмотром результата встроен как embed-контент в приложение на Go и отдаётся им
- Для редактирования Markdown используется **CodeMirror** + **marked.js** — легковесно, быстро, поддерживает live preview и Markdown-специфичные фичи
- Древовидное отображение заметок в веб-интерфейсе слева от области редактирования
- Поддержка создания папок и файлов в веб-интерфейсе с последующей передачей результата по REST в бэкенд, который сохраняет результат в настроенное хранилище
- Автосохранение результатов редактирования (debounce каждые 2 секунды после последнего изменения)
- Использование встраиваемой БД (**BoltDB**) **только для метаданных**: структура дерева, теги, настройки, информация о синхронизации Git
- Файлы Markdown хранятся в файловой системе по пути: `~/.igonotes/bases/<база>/<тема>/notes/...`
- Вспомогательные файлы (картинки, вложения) хранятся в подкаталоге `assets/images/` внутри каждой базы, например: `~/.igonotes/bases/<база>/assets/images/`
- Используется **go-git** (https://github.com/go-git/go-git) — чистый Go, не требует установленного git в системе
- Поддержка настройки базы как git-репозитория и периодической синхронизации с удалённым репозиторием по расписанию из настроек
- Метаданные заметок (название, дата создания/изменения, теги, родительская папка) хранятся в BoltDB
- Шифрование считаю на данном этапе излишним, но возможно стоит рассмотреть этот вариант в будущих реализациях
- По особенностям интерфейса:
  - Окно делится на две части: слева — древовидная структура базы заметок, справа — редактор Markdown с переключением между режимами редактирования и превью
  - В верхней или нижней части — панель инструментов для вставки Markdown-тегов (ссылки, изображения, заголовки и т.д.)
  - Возможность вставить ссылку на другую заметку через диалоговое окно выбора
  - Верхнее меню: "Файл", "Настройки", "Синхронизация", "Открыть другую базу"
- По стилю оформления и дизайну: использовать **Bootstrap** для современного и адаптивного UI

## Технологии

- **Бэкенд**: Go (1.21+)
- **Фронтенд**: HTML, CSS, JavaScript
  - Редактор: **CodeMirror**
  - Парсинг Markdown: **marked.js**
  - UI: **Bootstrap**
- **Хранение метаданных и настроек**: BoltDB
- **Хранение файлов**: файловая система
- **Git-синхронизация**: `go-git` (без внешних зависимостей)
- **Сборка и релиз**: gitverse.ru (аналог Gitea)

## Фронтенд: сборка и внедрение

- Фронтенд собирается в каталог `web/dist/` с помощью простого скрипта (без Webpack/Vite, чтобы не усложнять)
- Сборка выполняется перед основной компиляцией Go
- Весь контент из `web/dist/` внедряется в бинарник через `//go:embed`
- При изменении фронтенда он пересобирается и автоматически включается в бинарник при следующем `go build`

Пример:
```go
//go:embed web/dist/*
var staticFiles embed.FS
```

Рекомендуемая команда сборки:

```Bash
make build
```
Где Makefile содержит:

```MAKEFILE
build:
    npm run build  # если используется JS-сборка
    go build -o igonotes .
```

## Структура данных

```
~/.igonotes/
└── bases/
    └── <название_базы>/
        ├── <тема_1>/
        │   └── notes/
        │       ├── note1.md
        │       └── subtopic/
        │           └── note2.md
        ├── <тема_2>/
        │   └── notes/
        └── assets/
            └── images/
                └── diagram.png
```
```
~/.config/igonotes/
└── config.json
```

- Конфигурация приложения: ~/.config/igonotes/config.json (XDG-совместимо)
- BoltDB с метаданными: ~/.igonotes/metadata.db
- Каждая база может иметь .git/, если включена синхронизация

## REST API

| Метод | Путь | Описание |
|:---|:---|:--- |
| GET | /api/notes | Получить дерево заметок |
| GET | /api/notes/:id | Получить заметку по ID (или пути) |
| POST | /api/notes | Создать заметку или папку |
| PUT | /api/notes/:id | Обновить заметку |
| DELETE | /api/notes/:id | Удалить заметку или папку |
| POST | /api/assets | Загрузить изображение |
| PUT | /api/config | Сохранить настройки |
| POST | /api/git/sync | Запустить синхронизацию с Git |

## CLI-флаги
Поддерживаемые флаги:

- --config — путь к конфигурации (по умолчанию ~/.config/igonotes)
- --port — порт сервера (по умолчанию 8080)
- --base — имя базы для открытия
- --no-browser — не открывать браузер автоматически

Пример:

```Bash
igonotes --port 9000 --base work-notes
```

## Настройка при первом запуске

Если конфигурация отсутствует:

1. Сервер запускается, но вместо редактора открывается мастер настройки.
2. Мастер позволяет:
    - Создать новую базу или подключить существующую
    - Указать имя базы и путь к ней
    - Настроить Git (URL, автосинхронизация)

3. После завершения мастер сохраняет конфиг в ~/.config/igonotes/config.json и перенаправляет в основной интерфейс.

## Автосохранение

- На фронтенде реализован debounce (2 секунды после последнего изменения)
- При изменении текста отправляется PUT /api/notes/:id
- Бэкенд сохраняет .md файл в ФС и обновляет метаданные в BoltDB

## Работа с Git в заметках

- Реализовано через библиотеку go-git
- Фоновая горутина проверяет настройки и при необходимости делает:
    - git add .
    - git commit -m "Auto-sync"
    - git push

- Поддерживаются HTTPS и SSH (ключи из ~/.ssh)
- Ошибки выводятся в лог и могут отображаться во вкладке "Синхронизация"

## Работа с Git в проекте

Используется ветвевая модель:

- develop — основная ветка разработки.
- master — стабильная версия и релизы.
- pages — ветка для документации (Jekyll).

Правила внесения изменений:
1. Создаётся фича-ветка:
    ```Bash
    git checkout -b feature/note-search
    ```
2. Вносятся изменения, тестируются.
3. Делается коммит:
    ```Bash
    git add .
    git commit -m "Добавлен поиск заметок"
    ```
4. Отправляется в удалённый репозиторий:
    ```Bash
    git push origin feature/note-search
    ```
5. Создаётся Pull Request в develop.
6. Релиз осуществляется через gitverse.ru из ветки develop → master, устанавливается версия тегом.
