# IGoNotes — Редактор заметок на Go и Markdown

IGoNotes — это CLI-приложение на Go, которое при запуске поднимает локальный REST-сервер и открывает им же в браузере страничку веб-интерфейс для редактирования и сохранения Markdown-заметок. Проект должен поддерживать древовидную структуру каталогов за хранение которой отвечает бэкенд, редактирование и предварительный просмотр Markdown-заметок с поддержкой современных спецификаций Markdown, за это отвечает современное одностраничное приложение на Svelte, которое открывается в браузере бэкендом и отдаётся как статический контент.

## Особенности

- REST-сервер на Go
- При первом запуске нужна процедура настройки параметров и хранилища, возможно мастером, в веб-интерфейсе, там же предусмотреть возможность открытия уже имеющейся базы настроек
- REST-сервер при запуске должен поддерживать ключи командной строки, для передачи параметров запуска (где искать настройки как минимум), но они должны быть необязательны
- Настройки программы должны храниться в стандартном `~/.config` для Linux и таких же стандартных местах для Windows и macOS
- Сборку бинарника осуществлять для linux 386, amd64, windows 386, amd64, macos 386, amd64, arm64
- Хотелось бы использовать для сборки релиза возможности gitverse.ru (сборка как в Gitea)
- Веб-интерфейс с редактором Markdown и просмотром результата встроен как embed-контент в приложение на Go и отдаётся им
- Для редактирования Markdown используется **CodeMirror 6** + **marked.js** — современно, модульно, легковесно, поддерживает live preview и Markdown-специфичные фичи
- Древовидное отображение заметок в веб-интерфейсе слева от области редактирования
- Поддержка создания папок и файлов в веб-интерфейсе с последующей передачей результата по REST в бэкенд, который сохраняет результат в настроенное хранилище
- Автосохранение результатов редактирования (debounce каждые 2 секунды после последнего изменения)
- Использование встраиваемой реляционной БД (**SQLite** через `modernc.org/sqlite`, без CGO) **только для метаданных**: структура дерева, теги, настройки, информация о синхронизации Git
- Файлы Markdown хранятся в файловой системе по пути: `~/.igonotes/bases/<база>/<тема>/notes/...`
- Вспомогательные файлы (картинки, вложения) хранятся в подкаталоге `assets/images/` внутри каждой базы, например: `~/.igonotes/bases/<база>/assets/images/`
- Используется **go-git** (https://github.com/go-git/go-git) — чистый Go, не требует установленного git в системе
- Поддержка настройки базы как git-репозитория и периодической синхронизации с удалённым репозиторием по расписанию из настроек
- Метаданные заметок (название, дата создания/изменения, теги, родительская папка) хранятся в SQLite
- Шифрование считаю на данном этапе излишним, но возможно стоит рассмотреть этот вариант в будущих реализациях
- По особенностям интерфейса:
  - Окно делится на две части: слева — древовидная структура базы заметок, справа — редактор Markdown с переключением между режимами редактирования и превью
  - В верхней или нижней части — панель инструментов для вставки Markdown-тегов (ссылки, изображения, заголовки и т.д.)
  - Возможность вставить ссылку на другую заметку через диалоговое окно выбора
  - Верхнее меню: "Файл", "Настройки", "Синхронизация", "Открыть другую базу"
- По стилю оформления и дизайну: использовать **Tailwind CSS** для современного и адаптивного UI

## Технологии

- **Бэкенд**: Go (1.26+) (маршрутизация из коробки `net/http`)
- **Фронтенд**: Svelte, Vite
  - Редактор: **CodeMirror 6**
  - Парсинг Markdown: **marked.js**
  - UI: **Tailwind CSS**
- **Хранение метаданных и настроек**: SQLite (`modernc.org/sqlite`, чистый Go без CGO)
- **Хранение файлов**: файловая система
- **Git-синхронизация**: `go-git` (без внешних зависимостей)
- **Сборка и релиз**: gitverse.ru (аналог Gitea)

## Фронтенд: сборка и внедрение

- Фронтенд разрабатывается и собирается с помощью **Vite** в каталог `web/dist/`
- Сборка выполняется перед основной компиляцией Go
- Весь контент из `web/dist/` внедряется в бинарник через `//go:embed`
- При изменении фронтенда он пересобирается и автоматически включается в бинарник при следующем `go build`

Пример:
```go
//go:embed web/dist/*
var staticFiles embed.FS
```

**ВАЖНО:** Сборку проекта необходимо **ВСЕГДА** осуществлять через утилиту `make`. Это гарантирует правильную последовательность сборки (сначала UI, затем внедрение статики в бинарник Go).

Рекомендуемая команда полной сборки:

```Bash
make all
```
Где Makefile содержит разделение:

```MAKEFILE
all: ui go

ui:
	cd web && npm install && npm run build

go:
	mkdir -p builds
	go build -o builds/igonotes ./cmd/...
```

## Структура данных

```
~/.igonotes/
└── bases/
    └── <название_базы>/
        ├── <тема_1>/
        │   └── notes/
        │       ├── note1.md
        │       └── subtopic/
        │           └── note2.md
        ├── <тема_2>/
        │   └── notes/
        └── assets/
            └── images/
                └── diagram.png
```
```
~/.config/igonotes/
└── config.json
```

- Конфигурация приложения: ~/.config/igonotes/config.json (XDG-совместимо)
- SQLite с метаданными: ~/.igonotes/metadata.db
- Каждая база может иметь .git/, если включена синхронизация

## REST API

| Метод | Путь | Описание |
|:---|:---|:--- |
| GET | /api/notes | Получить дерево заметок |
| GET | /api/notes/:id | Получить заметку по ID (или пути) |
| POST | /api/notes | Создать заметку или папку |
| PUT | /api/notes/:id | Обновить заметку |
| DELETE | /api/notes/:id | Удалить заметку или папку |
| POST | /api/assets | Загрузить изображение |
| PUT | /api/config | Сохранить настройки |
| POST | /api/git/sync | Запустить синхронизацию с Git |

## CLI-флаги
Поддерживаемые флаги:

- --config — путь к конфигурации (по умолчанию ~/.config/igonotes)
- --port — порт сервера (по умолчанию 8080)
- --base — имя базы для открытия
- --no-browser — не открывать браузер автоматически

Пример:

```Bash
igonotes --port 9000 --base work-notes
```

## Настройка при первом запуске

Если конфигурация отсутствует:

1. Сервер запускается, но вместо редактора открывается мастер настройки.
2. Мастер позволяет:
    - Создать новую базу или подключить существующую
    - Указать имя базы и путь к ней
    - Настроить Git (URL, автосинхронизация)

3. После завершения мастер сохраняет конфиг в ~/.config/igonotes/config.json и перенаправляет в основной интерфейс.

## Автосохранение

- На фронтенде реализован debounce (2 секунды после последнего изменения)
- При изменении текста отправляется PUT /api/notes/:id
- Бэкенд сохраняет .md файл в ФС и обновляет метаданные в SQLite

## Работа с Git в заметках

- Реализовано через библиотеку go-git
- Фоновая горутина проверяет настройки и при необходимости делает:
    - git add .
    - git commit -m "Auto-sync"
    - git push

- Поддерживаются HTTPS и SSH (ключи из ~/.ssh)
- Ошибки выводятся в лог и могут отображаться во вкладке "Синхронизация"

## Работа с Git в проекте

Используется ветвевая модель:

- develop — основная ветка разработки.
- master — стабильная версия и релизы.
- pages — ветка для документации (Jekyll).

Правила внесения изменений:
1. Создаётся фича-ветка:
    ```Bash
    git checkout -b feature/note-search
    ```
2. Вносятся изменения, тестируются.
3. Делается коммит:
    ```Bash
    git add .
    git commit -m "Добавлен поиск заметок"
    ```
4. Отправляется в удалённый репозиторий:
    ```Bash
    git push origin feature/note-search
    ```
5. Создаётся Pull Request в develop.
6. Релиз осуществляется через gitverse.ru из ветки develop → master, устанавливается версия тегом.

## Текущий прогресс (добавлено в процессе разработки)
- **Go и зависимости:** Версия Go обновлена до 1.26. Успешно установлены зависимости `modernc.org/sqlite` и `go-git/v5`.
- **Фронтенд (Svelte + Vite):** 
  - Папка `web` очищена и инициализирована с нуля на базе Svelte 5 + Vite.
  - Настроен Tailwind CSS v4 (`@tailwindcss/vite`).
  - Установлены и интегрированы `CodeMirror 6` (с поддержкой Markdown) и `marked.js` для предпросмотра (c `@tailwindcss/typography`).
  - Сверстан базовый Layout приложения (`App.svelte`, `Sidebar.svelte`, `Editor.svelte`), поддерживающий переключение между режимами "Редактор" и "Превью".
- **Интеграция Бэкенда и Фронтенда:** 
  - Настроено внедрение собранного фронтенда (папка `web/dist`) напрямую в бинарник через `//go:embed all:dist` (файл `web/embed.go`).
  - Реализован `SPAHandler` (`internal/handlers/static_handler.go`) для раздачи `embed.FS` с fallback-ом на `index.html` (для корректной работы клиентского роутинга).
- **База данных (SQLite):**
  - Создан пакет `repository` (`db.go`, `note_repo.go`).
  - Настроена автоматическая инициализация БД (`~/.igonotes/metadata.db`) и создание таблиц `notes` и `tags` при запуске.
  - Проведен рефакторинг обработчиков (`note_handler.go`) и сервисов (`note_service.go`) — разделена логика HTTP и работы с данными. Подготовлен эндпоинт `GET /api/notes` для отдачи JSON с деревом.
- **Дерево заметок и синхронизация с ФС:**
  - Реализован метод `SyncFS` в `NoteService` для рекурсивного сканирования файловой системы и синхронизации структуры (папки и `.md` файлы) в SQLite с использованием относительных путей в качестве идентификаторов.
  - Написана эффективная сборка иерархического дерева из плоского списка БД в методе `GetTree`.
  - Фронтенд (`Sidebar.svelte`) переписан для загрузки реального дерева по REST API (`GET /api/notes`) с применением `{#snippet}` из Svelte 5 для рекурсивной отрисовки интерфейса любой вложенности.
- **Редактирование и сохранение заметок:**
  - Реализованы эндпоинты `GET /api/note?id=...` для чтения Markdown-файла с диска и `POST /api/save` для сохранения изменений.
  - Настроен проброс выбранной заметки из `Sidebar.svelte` в `App.svelte` с последующей загрузкой её содержимого.
  - На фронтенде реализован механизм debounce: автоматическое сохранение (отправка `POST` запроса) спустя 2 секунды после последнего изменения текста в CodeMirror. 
  - Добавлена визуальная индикация процесса сохранения ("Сохранение..." / "Сохранено") в верхней панели `App.svelte`.
  - Улучшен режим предварительного просмотра (Превью): чекбоксы задач (`- [ ]`) теперь интерактивны (при клике обновляют исходный Markdown-код заметки и триггерят автосохранение), а все внешние ссылки автоматически открываются в новой вкладке.
- **Управление заметками и папками (Создание/Переименование/Удаление):**
  - Реализованы эндпоинты `POST /api/notes` (создание файлов/папок), `DELETE /api/note` (удаление) и `PUT /api/rename` (переименование) в `NoteHandler` и `NoteService`.
  - В `internal/model/api.go` добавлены и уточнены структуры запросов (`CreateNoteRequest`, `SaveNoteRequest`, `RenameRequest`).
  - Разработан переиспользуемый компонент `Modal.svelte` на базе Tailwind для современных всплывающих диалогов.
  - В `Sidebar.svelte` встроена логика создания, удаления и переименования заметок через модальные окна. При удалении или переименовании активной заметки редактор корректно очищается.
  - Улучшен UX дерева: добавлена возможность создания файлов/папок в корне базы (сброс выделения кликом вне элементов), а также сохранение состояния раскрытых папок при обновлении дерева.
  - Реализована безопасная обработка конфликтов имен: если при создании файл или папка уже существует, бэкенд возвращает статус `409 Conflict`, а UI предупреждает пользователя и автоматически переключается на существующий элемент без его перезаписи.
  - Добавлена кнопка принудительного обновления дерева в интерфейсе `Sidebar.svelte` (полезно при внешних изменениях файлов).
  - Заголовок страницы в браузере (title) изменён на "IGoNotes".
  - Исправлен алгоритм сборки дерева заметок на бэкенде (`GetTree`), теперь корректно отображаются папки и файлы любого уровня вложенности (больше 1 уровня).
- **Исправления по итогам Code Review:**
  - Устранена потенциальная уязвимость Path Traversal в `SPAHandler` (`internal/handlers/static_handler.go`) — добавлена очистка путей с помощью `path.Clean()` и строгая проверка `fs.ValidPath()`.
  - Исправлена консистентность работы с ID папок во фронтенде: переменная `activeFolderId` в `Sidebar.svelte` теперь инициализируется и очищается через `null` (вместо `""`), что предотвращает логические ошибки при truthy-проверках, при этом для API по-прежнему корректно отправляется пустая строка (означающая корень).
  - Подтверждена корректность подключения плагина Tailwind Typography для Tailwind v4 (через `@plugin` в `app.css`).
  - Улучшена надежность автофокуса в модальных окнах: `setTimeout` с хардкодной задержкой заменен на `requestAnimationFrame`, что устраняет возможные race conditions при рендеринге Svelte.
  - Повышена стабильность переключения чекбоксов в режиме "Превью": вместо хрупких регулярных выражений теперь используется AST-парсинг от CodeMirror (`syntaxTree`), что гарантирует корректную работу со сложной Markdown-разметкой (например, чекбоксами внутри блоков кода).
- **Сборка проекта:** Добавлен полноценный `Makefile` с поддержкой раздельной сборки UI (`make ui`), бэкенда (`make go`), очистки (`make clean`) и полной сборки (`make all`). Результат сборки (`builds/igonotes`) теперь игнорируется в `.gitignore`.
- **UI/UX улучшения:**
  - Реализован надежный автофокус в модальных окнах (создание, переименование) через Svelte Action (`use:focusInput`). Это решило проблему, при которой HTML-атрибут `autofocus` не срабатывал при повторном открытии модалок в SPA.
- **Отображение изображений и медиафайлов:**
  - Реализован новый эндпоинт `GET /api/raw?path=...` для отдачи файлов (картинок) из текущей базы с защитой от Path Traversal (проверка выхода за пределы базовой директории).
  - На фронтенде добавлен препроцессинг Markdown: реализована поддержка Obsidian-синтаксиса `![[Имя файла.png]]` (в том числе устойчивость к опечаткам без закрывающих скобок).
  - Настроена маршрутизация всех относительных Markdown-ссылок на картинки (`![alt](image.png)`) через защищенный эндпоинт `/api/raw`, обеспечивая бесшовное отображение локальных файлов.
