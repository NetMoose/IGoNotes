# IGoNotes — Редактор заметок на Go и Markdown

IGoNotes — это CLI-приложение на Go, которое запускает локальный REST-сервер и открывает в браузере веб-интерфейс для редактирования Markdown-заметок. Проект поддерживает древовидную структуру каталогов, редактирование и предварительный просмотр Markdown с поддержкой современных спецификаций.

## Особенности

- Локальный REST-сервер и встроенный веб-интерфейс, открываемый в браузере
- Редактор Markdown с подсветкой синтаксиса, панелью форматирования и предпросмотром
- Дерево заметок: создание, переименование и удаление папок и файлов
- Автосохранение, вставка и загрузка изображений
- Несколько локальных баз с настройками и переключением без перезапуска
- SQLite для метаданных; Markdown и изображения остаются обычными файлами
- Опциональная двусторонняя Git-синхронизация нескольких устройств с явным разрешением конфликтов
- Web Clipper для настольного Chromium: Article/Selection, локальные черновики и изображения, ручная отправка в выбранную базу

## Технологии

- **Бэкенд**: Go (1.26+), `net/http`
- **Фронтенд**: Svelte 5, Vite 8, Tailwind CSS 4, CodeMirror 6, marked.js
- **Хранение**: Markdown-файлы и SQLite (`modernc.org/sqlite`)
- **Git**: внешний системный Git 2.28+; необязателен для локальной работы
- **Сборка и релиз**: GitHub Actions

## Начало работы

Для сборки из исходного кода нужны Go 1.26+, Node.js 24, npm и GNU Make. `make all` устанавливает frontend-зависимости по lockfile, собирает интерфейс и встраивает его в бинарник.

```bash
# Полная сборка frontend и backend
make all

# Запуск собранного приложения
./builds/igonotes
```

Сервер слушает `http://127.0.0.1:8080`, браузер открывается автоматически. При первом запуске мастер предложит создать или подключить базу. Для установленного в PATH бинарника команда запуска — `igonotes`.

Проверки из корня проекта:

```bash
# Frontend-тесты и сборка, Go-тесты, race detector и go vet
make verify

# Обязательные интеграционные проверки с реальным системным Git
make test-git
```

`make test-git` требует Git 2.28+ и включает обязательный режим Git-интеграционных тестов.

## Web Clipper: от страницы до заметки

Доступны захват, редактор, подготовка изображений, ручной Send и восстановление после перезапуска. Расширение устанавливается из исходников отдельно от Go-приложения. В manifest объявлен Chrome/Chromium 120+, фактически проверен Linux Chromium **154.0.8037.97**. Полная Chrome/platform/manual-permission приёмка и CI/distribution остаются задачами раздела 9; native image permissions в smoke были test-only pregranted.

1. При **Node.js 24** соберите расширение из корня репозитория:

   ```sh
   node --version
   npm --prefix extensions/webclipper ci
   npm --prefix extensions/webclipper run verify
   ```

   Откройте `chrome://extensions` → **Developer mode** → **Load unpacked**, выберите `extensions/webclipper/dist` целиком, включая лицензии.
2. На HTTP(S)-странице нажмите в popup **Article** либо заранее выделите диапазон главного документа и нажмите **Selection**. Сервер для захвата не нужен. Дождитесь **Saved locally** — черновик записан в IndexedDB, затем открывается отдельный редактор. Если вкладка не открылась, используйте **Open saved draft**, не повторный захват.
3. Проверьте **Title**, **Filename**, **Markdown**, нажмите **Save**. Имя `.md` можно выбрать вручную; правка заголовка его не заменяет. **Download Markdown** скачивает YAML (`title`, `source`, `clipped_at`) и текущий, даже несохранённый body, без изображений.
4. Нажмите **Prepare images**; при ошибке — **Retry images / grant access**. Разрешение запрашивается явно для конкретных схемы/хоста (Chrome patterns охватывают все порты). **Stored locally** означает подтверждённые сохранённые Blob-байты, не просто удачный fetch. Для допустимого HTTP(S)-источника можно отдельно выбрать **Keep external reference**, проверить URL/причину и нажать **Confirm external references**. Один чекбокс не подтверждает fallback; неподтверждённые ошибки блокируют Send. Внешние ссылки могут требовать сети при последующем рендеринге; выбор сбрасывается при правке body/источника, Retry или повторном открытии.
5. **Перед созданием подключения для отправки** нужен совместимый Go-бинарник из **текущего checkout** либо другая сборка с заведомой поддержкой Web Clipper protocol v1 и UI подключений. Нельзя предполагать такую поддержку у уже установленного/опубликованного бинарника. Для воспроизводимого запуска выполните из корня репозитория при **Node.js 24 и Go 1.26+**:

   ```sh
   node --version
   go version
   make all
   ./builds/igonotes --port 9000
   ```

   Go-сборка не нужна для локального захвата/редактирования/подготовки изображений. Bare `igonotes --port 9000` допустим только для заведомо совместимого PATH-бинарника. Завершите настройку базы в запущенном приложении. Затем: **Настройки → Веб-клиппер → Название подключения → Создать подключение**, скопируйте одноразовый **Секрет подключения**. В расширении: **Connection settings**, **Endpoint** `http://127.0.0.1:9000`, **Connection token**, **Save connection**, затем явно **Test connection**. Сохранение настроек сеть не вызывает.
6. Нажмите **Load destinations**, выберите **Destination base** и существующую **Destination folder**, явно `(root)` для корня; нажмите **Confirm destination**, затем **Send**. Автовыбора базы/папки нет. Дождитесь **Import confirmed**: receipt с историческими базой/путём, ревизией и предупреждениями. Импорт создаёт новую заметку и проверенные изображения `assets/images/clip-<import_id>-<sha256>.<ext>`, не перезаписывает существующее имя (`409 note_conflict`).
7. Импорт не переключает активную базу IGoNotes: выберите исходную целевую базу через **Настройки → Базы заметок** и при необходимости нажмите над деревом **Обновить дерево (Синхронизировать с диском)**. Send не выполняет Git push; обычная ручная/автоматическая Git-синхронизация работает отдельно.

**Если ответ потерян:** сохраните замороженную попытку и её изображения. **Check attempt** делает только GET; **Check / retry exact attempt** делает GET и только при unknown повторяет POST с прежними ID, payload и revision. Неизвестный GET `400` не доказывает отсутствия файлов. Не меняйте frozen payload и не создавайте новый ID для обхода timeout/5xx, pending/recovery или identity conflict. Смена endpoint блокирует GET/POST старой попытки; восстановите исходный адрес (новый токен там допустим). После restart сервера **новая** отправка требует Load/выбор/Confirm заново, исторический успех проверяется старым ID. Подробные различия отказа, неопределённого исхода и локальной cleanup — в [руководстве](docs/user.md#ручная-отправка-и-неопределённый-результат).

Поддерживаются статические PNG/JPEG/WebP и GIF, включая все кадры анимации; APNG/animated WebP/SVG/PDF не поддерживаются. Cookie-protected изображения могут не загрузиться (`credentials: omit`), redirects (включая CDN 302) не следуются; blob/canvas/private/unsafe источники не обходятся. Подготовка обрабатывает Markdown-изображения, raw HTML `<img>` не управляется. Лимиты: 10 MiB/изображение, 50 MiB и 100 уникальных assets/импорт, 5 MiB полного Markdown с YAML, 64 MiB wire; 40 МП/изображение/canvas/кадр, 100 GIF-кадров/200 МП суммарно. Локально — 50 черновиков и 250 MiB физических Blob плюс metadata overhead; квота браузера может закончиться раньше. Кэшированные байты переживают закрытие страницы/браузера, но незавершённые загрузки требуют ручного Prepare. Автоматического backup профиля нет.

Полный [пользовательский гид](docs/user.md#веб-клиппер-подключения-браузера), [README расширения](extensions/webclipper/README.md) с модульными API, лицензиями и smoke-командами и [контракт API](docs/api.md#web-clipper-v1--discovery-и-http-import-доступны).

Автоматическая межкомпонентная проверка (Linux, установленный Chromium, Xvfb при
отсутствии `DISPLAY`; Node.js 24, Go 1.26+):

```sh
node --version
npm --prefix web ci
npm --prefix web run build
npm --prefix extensions/webclipper ci
npm --prefix extensions/webclipper run test:browser
```

`test:browser` сначала выполняет extension `verify` со свежим `dist`, затем собирает
Go из текущего checkout и запускает четыре native MV3 режима и пять fault-проверок
на локальных HTTP fixtures. JSON-отчёт: `extensions/webclipper/tests/browser/results.json`.
Зависимости и браузер устанавливаются заранее; во время browser suite загрузок нет.
Watchdog cleanup использует общий приватный журнал владения процессами: detached
группы и профили удаляются и при остановке supervisor/checker без передачи stdout.
[Матрица, переменные окружения и отдельные manual-сценарии](extensions/webclipper/tests/browser/README.md).
Официальный Chrome и настоящие permission prompts относятся к отдельной приёмке 9.2.

## Git-синхронизация

Git необязателен для обычных локальных баз. Для синхронизации нужен системный Git 2.28 или новее, заранее настроенная неинтерактивная авторизация через SSH-agent, credential helper или Git config и Git identity (`user.name`, `user.email`). IGoNotes не хранит HTTPS-токены и SSH-ключи и не запрашивает пароль в терминале.

Интеграция настраивается отдельно для каждой базы: `origin`, ветка, ручной режим или автоматический интервал 5/15/30/60 минут (по умолчанию 15) и шаблон сообщения коммита. Sync фиксирует все неигнорируемые файлы базы через `git add -A`, получает удаленные изменения, выполняет обычное слияние и push без rebase или force-push. Конфликты разрешаются явно в интерфейсе. После пяти последовательных операционных ошибок синхронизация приостанавливается до явного возобновления.

Подключение, работа с двумя устройствами, статусы, конфликты и отключение описаны в [руководстве пользователя](docs/user.md#git-синхронизация).
