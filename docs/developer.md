# Руководство разработчика IGoNotes

Добро пожаловать в команду разработчиков IGoNotes! Этот документ поможет вам начать работу с кодовой базой.

## Структура проекта

- `cmd/api/main.go` — точка входа приложения.
- `internal/service/` — бизнес-логика.
- `internal/repository/` — работа с BoltDB и файловой системой.
- `internal/model/` — структуры данных (Note, Node и т.д.).
- `web/` — статические файлы и шаблоны.

## Зависимости

- **Go 1.21+**
- **BoltDB** — встраиваемая БД для метаданных.
- **CodeMirror**, **marked.js**, **Bootstrap** — клиентский фронтенд.
- **go-git** — для Git-синхронизации без внешних зависимостей.

## Запуск и сборка

```bash
# Установка зависимостей
go mod tidy

# Запуск сервера
go run ./cmd/api --port 8080

# Сборка бинарника
go build -o igonotes cmd/api/main.go
```

Рекомендуемая команда сборки:

```Bash
make build
```

Где `Makefile` содержит:

```makefile
build:
    npm run build  # если используется JS-сборка
    go build -o igonotes .
```

## Фронтенд: сборка и внедрение

- Фронтенд собирается в каталог `web/dist/` с помощью простого скрипта (без Webpack/Vite, чтобы не усложнять)
- Сборка выполняется перед основной компиляцией Go
- Весь контент из `web/dist/` внедряется в бинарник через `//go:embed`
- При изменении фронтенда он пересобирается и автоматически включается в бинарник при следующем `go build`

Пример:
```go
//go:embed web/dist/*
var staticFiles embed.FS
```

## Структура данных

```
~/.igonotes/
└── bases/
    └── <название_базы>/
        ├── <тема_1>/
        │   └── notes/
        │       ├── note1.md
        │       └── subtopic/
        │           └── note2.md
        ├── <тема_2>/
        │   └── notes/
        └── assets/
            └── images/
                └── diagram.png
```

```
<os.UserConfigDir()>/
└── igonotes/
    └── config.json
```

- Конфигурация приложения: `<os.UserConfigDir()>/igonotes/config.json`, где `os.UserConfigDir()` предоставляет системный каталог конфигурации. В Linux каталог конфигурации приложения — `$XDG_CONFIG_HOME/igonotes`, если `XDG_CONFIG_HOME` задана; иначе `~/.config/igonotes`.
- BoltDB с метаданными: `~/.igonotes/metadata.db`
- Каждая база может иметь `.git/`, если включена синхронизация

## Работа с Git

Мы используем ветвевую модель:

- `develop` — основная ветка разработки.
- `master` — стабильная версия.
- `pages` — ветка для документации (Jekyll).

### Правила внесения изменений:

1. Создайте фича-ветку:
   ```bash
   git checkout -b feature/note-search
   ```
2. Вносите изменения, тестируйте.
3. Сделайте коммит:
   ```bash
   git add .
   git commit -m "Добавлен поиск заметок"
   ```
4. Отправьте в удалённый репозиторий:
   ```bash
   git push origin feature/note-search
   ```
5. Создайте Pull Request в `develop`.

## REST API

| Метод | Путь | Описание |
|:---|:---|:--- |
| GET | `/api/notes` | Получить дерево заметок |
| GET | `/api/notes/:id` | Получить заметку по ID (или пути) |
| POST | `/api/notes` | Создать заметку или папку |
| PUT | `/api/notes/:id` | Обновить заметку |
| DELETE | `/api/notes/:id` | Удалить заметку или папку |
| POST | `/api/assets` | Загрузить изображение |
| PUT | `/api/config` | Сохранить настройки |
| POST | `/api/git/sync` | Запустить синхронизацию с Git |

## CLI-флаги

Поддерживаемые флаги:

- `--config` — каталог конфигурации (по умолчанию `<os.UserConfigDir()>/igonotes`)
- `--port` — порт сервера (по умолчанию 8080)
- `--base` — имя уже настроенной базы, присутствующее в `config.json`
- `--no-browser` — не открывать браузер автоматически
