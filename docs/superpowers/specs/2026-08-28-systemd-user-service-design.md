# Пользовательский systemd-сервис IGoNotes

## Цель

Позволить пользователю Linux запускать локальный сервер IGoNotes как пользовательский systemd-сервис без автоматического открытия вкладки браузера. Установленное Chromium/PWA-приложение остаётся отдельным клиентом и подключается к уже работающему серверу по постоянному loopback-адресу.

Флаг `--no-browser` и устанавливаемый PWA-интерфейс уже реализованы. Изменение добавляет управление жизненным циклом user-unit, безопасное завершение серверного процесса и пользовательскую документацию.

## Пользовательский сценарий

CLI получает две команды:

```text
igonotes service install [--port PORT] [--config DIR] [--base NAME]
igonotes service uninstall
```

`service install`:

- использует обычные значения запуска IGoNotes, если опции не переданы;
- сохраняет явно переданные `--port`, `--config` и `--base` в `ExecStart`;
- всегда добавляет `--no-browser`;
- использует абсолютный путь текущего бинарника, не копируя его;
- устанавливает и немедленно запускает `igonotes.service`;
- включает автоматический запуск сервиса при входе пользователя.

Порт по умолчанию фиксируется в unit как `8080`. Явно переданный относительный `--config` преобразуется в абсолютный путь относительно каталога, из которого выполняется установка. Неуказанные `--config` и `--base` остаются неуказанными в `ExecStart`, поэтому сервер применяет свои обычные значения по умолчанию. Пользователь обязан сохранять бинарник по пути, записанному при установке; после перемещения бинарника следует повторно выполнить `service install` из нового расположения.

Повторный `service install` атомарно обновляет принадлежащий IGoNotes unit и перезапускает сервис с новыми параметрами.

`service uninstall` останавливает и отключает сервис, удаляет принадлежащий IGoNotes unit и обновляет состояние user-systemd. Команда не удаляет бинарник, конфигурацию, SQLite-метаданные, базы или заметки.

Обычный запуск `igonotes [--port ...]` сохраняет текущее поведение на всех ОС. На macOS, Windows и Linux без доступного пользовательского systemd команды `service` возвращают понятную ошибку до изменения файлов.

## Связь с Chromium/PWA

Установка systemd-сервиса не устанавливает и не запускает Chromium/PWA-приложение. Рекомендуемая последовательность:

1. Выполнить `igonotes service install` с требуемым постоянным портом.
2. Открыть выведенный командой адрес, по умолчанию `http://127.0.0.1:8080`.
3. Установить страницу штатным средством Chromium как приложение.
4. В дальнейшем запускать установленное веб-приложение, пока backend автоматически работает в пользовательской сессии.

PWA привязан к origin, включая порт. После изменения порта сервиса пользователь должен открыть и при необходимости установить приложение для нового origin; старый ярлык продолжит обращаться к прежнему порту.

## Область поддержки

Интеграция поддерживает Linux с пользовательским экземпляром systemd. Unit привязывается к `default.target`, поэтому запускается при входе пользователя. Команда не вызывает `sudo`, не создаёт системный unit и не включает linger; сервер не обязан работать до входа или после полного завершения пользовательской сессии.

## CLI и компоненты

Точка входа сначала распознаёт `service install` и `service uninstall`. Все остальные аргументы передаются обычному серверному запуску, чтобы существующий CLI-контракт не изменился.

Логика управления systemd отделяется от запуска HTTP-сервера и включает:

- разбор опций сервисной команды;
- получение абсолютного пути текущего executable;
- формирование и проверку владения unit-файлом;
- атомарную запись и удаление unit;
- запуск `systemctl` без shell через внедряемый command runner.

Command runner и операции определения окружения должны быть заменяемыми в тестах. Реальный `systemctl` не требуется для автоматических unit-тестов.

## Unit-файл

Unit хранится по пути `<os.UserConfigDir()>/systemd/user/igonotes.service`. Параметр IGoNotes `--config` влияет только на конфигурацию приложения и не меняет расположение systemd unit.

Файл содержит:

```ini
# Managed by IGoNotes
[Unit]
Description=IGoNotes local note server

[Service]
Type=simple
ExecStart=<escaped absolute executable> --port <escaped port> [--config <escaped dir>] [--base <escaped name>] --no-browser
Restart=on-failure
RestartSec=3

[Install]
WantedBy=default.target
```

`ExecStart` формируется без shell. Путь и значения аргументов экранируются по синтаксису systemd, включая пробелы, кавычки, обратные слеши и `%`. Стандартные stdout и stderr остаются подключёнными к user journal.

Unit намеренно не задаёт рабочий каталог и не включает ограничения доступа к домашнему каталогу: серверу необходим доступ к пользовательским каталогам баз и системному выбору директории.

## Установка

До изменения файлов `service install`:

1. Проверяет, что ОС — Linux.
2. Проверяет синтаксис команды, допустимый диапазон порта и путь executable, а также нормализует явно переданный `--config` до абсолютного пути.
3. Проверяет наличие `systemctl` и доступность пользовательского экземпляра systemd.
4. Проверяет существующий `igonotes.service`, если он есть.

Существующий unit можно заменить только при наличии точного маркера `# Managed by IGoNotes`. Файл без маркера считается пользовательским, не перезаписывается и приводит к ошибке с указанием его пути.

После проверок команда:

1. Создаёт каталог `systemd/user`, если он отсутствует.
2. Записывает unit с правами `0644` во временный файл рядом с целевым.
3. Атомарно переименовывает временный файл в `igonotes.service`.
4. Выполняет `systemctl --user daemon-reload`.
5. Выполняет `systemctl --user enable igonotes.service`.
6. Выполняет `systemctl --user restart igonotes.service`.

Отдельный `restart` обязателен: `enable --now` не гарантирует перезапуск уже активного сервиса после обновления unit. Успешная команда печатает адрес сервера, путь unit и краткие команды диагностики.

## Удаление

`service uninstall` проверяет маркер перед удалением существующего файла. Unit без маркера не останавливается и не удаляется.

Для принадлежащего IGoNotes unit команда:

1. Выполняет `systemctl --user disable --now igonotes.service`.
2. Удаляет unit-файл.
3. Выполняет `systemctl --user daemon-reload`.

Отсутствующий по целевому пути unit считается уже удалённым: команда завершается успешно и не вызывает `disable`, чтобы не затронуть одноимённый unit из другого каталога поиска systemd.

## Завершение сервера

Сервис должен корректно обрабатывать `SIGTERM`, который systemd отправляет при остановке и перезапуске, и `SIGINT` при обычном завершении из терминала. Точка входа переводит запуск HTTP-сервера на управляемый жизненный цикл:

- сигнал отменяет контекст сервера;
- HTTP-сервер прекращает принимать новые соединения;
- активным операциям даётся 10 секунд на завершение;
- после остановки выполняются существующие `Close()` для note service и SQLite.

Истечение таймаута завершения регистрируется как ошибка, после чего процесс прекращает работу. Это также улучшает обычное завершение через сигнал в терминале, которое сейчас обходит отложенное закрытие ресурсов.

## Ошибки и безопасность

Файловые операции и команды systemd не используют shell и не требуют повышенных прав. Unit записывается атомарно, чтобы systemd не увидел частичное содержимое.

Ошибка каждого этапа содержит название операции и исходную причину. Для ошибки запуска сервера сообщение также предлагает:

```text
systemctl --user status igonotes.service
journalctl --user-unit igonotes.service
```

Если unit успешно записан, но `daemon-reload`, `enable` или `restart` завершается ошибкой, новый файл сохраняется для диагностики и последующего исправления повторным `service install`. Автоматический откат не выполняется, чтобы не скрывать актуальную желаемую конфигурацию.

Занятый порт и другие ошибки самого сервера видны в user journal. Сервис использует `Restart=on-failure`; пользователь может исправить параметры повторной установкой или удалить сервис.

## Тестирование

Автоматические Go-тесты покрывают:

- распознавание `service install` и `service uninstall` без регрессии обычного CLI;
- значения по умолчанию и переопределения `--port`, `--config`, `--base`;
- отказ для неизвестных команд, флагов, недопустимого порта и неподдерживаемой ОС;
- точное содержимое unit и экранирование сложных путей и аргументов;
- защитный маркер и отказ изменять чужой unit;
- атомарную установку и идемпотентное удаление во временном XDG-каталоге;
- порядок вызовов `systemctl` и ошибки каждого этапа через fake runner;
- мягкое завершение HTTP-сервера по отмене контекста/сигналу.

Ручная проверка на Linux с работающим user-systemd:

```bash
igonotes service install
systemctl --user status igonotes.service
curl http://127.0.0.1:8080/api/info
igonotes service install --port 9000
journalctl --user-unit igonotes.service
igonotes service uninstall
```

Дополнительно проверяются автоматический старт после нового входа в пользовательскую сессию и запуск установленного Chromium/PWA-приложения без автоматического открытия обычной вкладки.

## Документация

Обновляются `docs/user.md` и зеркальное руководство сайта. Документация описывает:

- ограничение Linux/systemd и отсутствие `sudo`;
- установку, повторную настройку и удаление сервиса;
- запуск при входе пользователя и отсутствие linger;
- зависимость Chromium/PWA от выбранного порта;
- требование сохранять бинарник по записанному абсолютному пути;
- команды `systemctl` и `journalctl` для диагностики.

Frontend, web app manifest, REST API, конфигурационные модели и формат заметок не изменяются.

## Не входит в изменение

- Системный root-unit.
- Автоматическое включение user linger.
- Аналоги systemd для macOS и Windows.
- Копирование, обновление или удаление бинарника.
- Автоматическая установка или запуск Chromium/PWA.
- Выделенный UI для управления backend-сервисом.
- Несколько одновременно установленных экземпляров user-unit.
