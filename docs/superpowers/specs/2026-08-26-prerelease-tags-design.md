# Автоматическое определение предварительных релизов

## Цель

Разрешить публикацию alpha, beta и release candidate версий из `develop`, не сливая изменения в `master`, и автоматически отмечать такие GitHub Releases как Pre-release.

## Правило Тегов

- Тег с дефисом после версии считается предварительным: `v0.1.0-alpha.1`, `v0.1.0-beta.1`, `v0.1.0-rc.1`.
- Тег без дефиса считается стабильным: `v0.1.0`.
- Существующий trigger `v*` остаётся без изменений.

## Изменение Workflow

В шаг публикации `.github/workflows/release.yml` добавить переменную `PRERELEASE`, вычисляемую выражением `contains(github.ref_name, '-')`.

Команду публикации перевести в shell-блок. Если `PRERELEASE` равно `true`, команда `gh release create` получает аргумент `--prerelease`; иначе релиз создаётся без этого аргумента. Сборка архивов, аудит, тесты и генерация checksums не меняются.

## Проверка

- Для `v0.1.0-alpha.1` вычисляется аргумент `--prerelease`.
- Для `v0.1.0` дополнительный аргумент отсутствует.
- YAML не содержит двух дублирующих шагов публикации.
- После публикации первого alpha-тега GitHub Release имеет признак Pre-release.
