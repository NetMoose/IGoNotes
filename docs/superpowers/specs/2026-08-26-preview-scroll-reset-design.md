# Сброс прокрутки preview при смене заметки

## Цель

При выборе другой заметки в режиме предварительного просмотра новая заметка должна открываться с начала, при этом приложение остаётся в режиме просмотра.

## Причина

`Editor` сохраняется между переключениями заметок. Preview использует тот же scroll-контейнер, поэтому обновление Markdown меняет его содержимое, но браузер сохраняет прежний `scrollTop`.

## Решение

- `App.svelte` передаёт в `Editor` идентификатор активной заметки через prop `noteId`.
- `Editor.svelte` принимает `noteId` вместе с bindable `content`.
- Preview scroll-контейнер оборачивается в Svelte-блок `{#key noteId}`.
- При изменении `noteId` пересоздаётся только preview-контейнер, и его начальная позиция прокрутки равна нулю.

Состояние `mode` остаётся внутри `Editor`, поэтому смена заметки не переключает пользователя из preview в edit. Изменения содержимого в пределах той же заметки не меняют `noteId` и не сбрасывают прокрутку.

## Проверка

- Открыть длинную заметку и перейти в preview.
- Прокрутить preview в середину.
- Выбрать в дереве другую длинную заметку.
- Убедиться, что режим preview сохранился, а новая заметка отображается с начала.
- Убедиться, что изменение checkbox текущей заметки не сбрасывает прокрутку.
- Собрать frontend без ошибок.
