# Руководство пользователя IGoNotes

IGoNotes запускает локальный сервер и открывает редактор Markdown-заметок в браузере.

Приложение использует Go 1.26+, Svelte 5, Vite 8, Tailwind CSS 4 и CodeMirror 6. Заметки хранятся как Markdown-файлы, метаданные — в SQLite. Git-синхронизация необязательна: локальными базами можно пользоваться без Git.

## Запуск приложения

Запустите установленный бинарник:

```bash
igonotes
```

Сервер слушает только локальный адрес `http://127.0.0.1:8080`, а браузер открывается автоматически. Если браузер не открылся, перейдите по этому адресу вручную.

Поддерживаемые флаги:

- `--config`: каталог конфигурации; по умолчанию используется `<os.UserConfigDir()>/igonotes`.
- `--port`: порт локального сервера; значение по умолчанию `8080`.
- `--base`: имя уже настроенной базы, которую нужно открыть при запуске.
- `--no-browser`: не открывать браузер автоматически.

Например:

```bash
igonotes --port 9000 --base work-notes --no-browser
```

## Запуск как пользовательский сервис Linux

В Linux IGoNotes можно установить как пользовательский сервис systemd. Команда создает юнит текущего пользователя в `$XDG_CONFIG_HOME/systemd/user/igonotes.service`, если `XDG_CONFIG_HOME` задана, иначе в `~/.config/systemd/user/igonotes.service`. Сервис запускается сразу и включается для следующих входов пользователя в систему или пользовательских сессий.

```bash
igonotes service install --port 9000 --config /path/to/config --base work-notes
```

Если параметры не указаны, используются обычные значения по умолчанию. Повторная установка обновляет юнит и перезапускает сервис. Сервис всегда добавляет `--no-browser` при запуске, поэтому обычная вкладка браузера автоматически не открывается.

Не редактируйте и не заменяйте `igonotes.service` одновременно с выполнением `igonotes service install` или `igonotes service uninstall`. Файловая блокировка координирует только параллельные вызовы IGoNotes; конкурентные изменения другими процессами того же пользователя или прямыми командами user-systemd не поддерживаются.

Юнит хранит абсолютный путь к текущему бинарнику, но не копирует его. Выберите для бинарника стабильный путь: перемещение или удаление файла нарушит `ExecStart`. После перемещения бинарника или изменения пути повторно выполните `igonotes service install` из нового расположения.

Для пользовательского сервиса не нужны `sudo`, права `root` или системный юнит. IGoNotes не включает user linger автоматически, поэтому запуск до входа пользователя в систему и работа после завершения его последней сессии не гарантируются.

Состояние сервиса и журнал можно проверить командами:

```bash
systemctl --user status igonotes.service
journalctl --user-unit igonotes.service
```

Чтобы использовать IGoNotes как Chromium PWA, сначала установите сервис на стабильном порту, затем откройте в Chromium точный loopback-адрес, например `http://127.0.0.1:9000`, и установите приложение средствами браузера. Origin PWA включает порт: после смены порта нужно открыть и установить новый origin. Команды `igonotes service` не устанавливают и не запускают Chromium PWA.

Удаление сервиса выполняется командой:

```bash
igonotes service uninstall
```

Она останавливает и отключает сервис, а затем удаляет пользовательский юнит с точным маркером управления IGoNotes. Бинарник, конфигурация, метаданные, базы и заметки не удаляются.

Команды `igonotes service` не поддерживаются в Windows и macOS. На этих платформах остаются доступны обычный запуск и флаг `--no-browser`.

## Настройка при первом запуске

При новой или пустой конфигурации появляется обязательный мастер. До его завершения редактор недоступен. Настройка состоит ровно из трех шагов:

1. Выберите создание новой базы или подключение существующей.
2. Укажите имя и каталог. Кнопка `Обзор` открывает системный выбор каталога; если он недоступен, путь можно ввести вручную.
3. Проверьте итоговый путь и завершите настройку.

В режиме создания выбранный каталог является родительским: новая база создается по пути `<directory>/<name>`. Родительский каталог должен существовать, а итоговый путь не должен быть занят.

В режиме подключения укажите точный путь к существующему каталогу. Мастер подключает его на месте и не перемещает и не изменяет его содержимое.

## Интерфейс

- Слева находится дерево папок и заметок с командами создания, переименования, удаления и обновления.
- Справа находится редактор CodeMirror с режимами редактирования и предварительного просмотра.
- Панель инструментов вставляет заголовки, списки, ссылки, таблицы, блоки кода и другое Markdown-форматирование.
- В верхней части редактора доступны индикатор сохранения, кнопка `Сохранить` и кнопка с шестеренкой для настроек.
- В строке состояния внизу отображается путь текущей базы.

## Редактирование заметок

Выберите заметку в дереве или создайте новую. Изменения автоматически сохраняются через 2 секунды после последнего ввода. Кнопка `Сохранить` выполняет сохранение немедленно.

Изображения можно добавить кнопкой панели инструментов, вставкой из буфера обмена или перетаскиванием. Загруженные файлы сохраняются в `assets/images/`; предпросмотр поддерживает обычные Markdown-ссылки и Obsidian-формат `![[image.png]]`.

### Конфликт изменений заметки

Окно `Конфликт изменений` появляется только в двух случаях: сохранение вернуло `409 note_changed` либо терминальный Git-статус содержит путь открытой заметки в `changed_paths`, а в редакторе есть несохраненные правки. IGoNotes не отслеживает произвольные изменения файловой системы. При входящих изменениях чистая заметка перечитывается автоматически, а удаленная чистая заметка закрывается. В окне показаны `Моя версия` и `Версия на диске`.

- `Загрузить версию с диска` явно отбрасывает несохраненный текст редактора и открывает актуальный файл; грязный редактор не заменяется автоматически входящими изменениями.
- `Оставить мою версию` требует отдельного действия `Подтвердить перезапись` и перезаписывает актуальный файл на диске.
- `Объединить вручную` открывает поле итогового текста; после редактирования нажмите `Сохранить объединение`.
- Если файл был удален на диске, доступна только команда `Закрыть заметку`: редактор закроется, а удаленный файл не будет создан заново автоматически.

Пока окно открыто, нельзя перейти к другой заметке, в настройки или переключить базу. Сначала выберите один из вариантов восстановления.

## Git-синхронизация

### Что нужно подготовить

Для опциональной двусторонней синхронизации установите системный Git 2.28 или новее. Для каждой базы используются один remote `origin` и одна выбранная ветка. У пользователя должны быть права чтения репозитория и отправки изменений в эту ветку, а также настроенная Git identity: `user.name` и `user.email` в пользовательском или локальном Git config.

Авторизацию настройте заранее вне IGoNotes: SSH-agent с доступным ключом, credential helper для HTTPS либо подходящий Git config. Она должна работать неинтерактивно в окружении процесса IGoNotes, в том числе пользовательского сервиса. Приложение не устанавливает Git, не хранит токены или SSH-ключи и не открывает интерактивные запросы пароля. Недоступная авторизация приводит к ошибке операции.

HTTP(S)-адреса с userinfo (логином, паролем или токеном), query-параметрами или fragment отклоняются. Не вставляйте токены в URL; используйте чистый адрес репозитория и внешний credential helper.

Git hooks создания коммитов (commit hooks) и настроенная подпись коммитов остаются активны. Их ошибка или требование интерактивного ввода может прервать операцию. Отправка изменений выполняется с `git push --no-verify`, поэтому локальный hook `pre-push` пропускается. При синхронизации коммитятся **все неигнорируемые файлы базы**, включая изображения и файлы не в формате Markdown; исключения задаются через `.gitignore`.

### Подключение: четыре шага

Откройте настройки шестеренкой, раздел `Git`, найдите карточку базы и нажмите `Настроить Git` или `Изменить настройки`.

1. **Репозиторий.** Введите URL и нажмите `Проверить репозиторий`. Проверка доступности обнаруживает удаленные ветки, не изменяя `.git`, refs, файлы, remote или конфигурацию базы.
2. **Ветка.** Выберите обнаруженную ветку. Для действительно пустого remote введите имя в поле `Новая ветка`. Пустота означает отсутствие всех объявленных refs: репозиторий с одними tags не считается пустым. После выбора выполняется повторная проверка; отсутствующую ветку непустого remote подключить нельзя.
3. **Расписание и коммиты.** Выберите `Только вручную` или `Автоматически`. Разрешены только интервалы **5, 15, 30 и 60 минут**, по умолчанию — **15 минут**. Задайте `Шаблон сообщения коммита` и проверьте предпросмотр.
4. **Подтверждение.** Проверьте URL, ветку, расписание и предупреждения. Если требуются изменения, явно подтвердите `Создать Git-репозиторий`, `Заменить origin`, `Создать ветку` или `Объединить несвязанные истории`. Добавление отсутствующего origin показывается отдельно, без отдельного флажка. Нажмите `Сохранить Git-настройки` и дождитесь итогового статуса: принятие операции не означает завершения подключения.

Шаблон по умолчанию — `IGoNotes: sync {{base}} at {{datetime}} ({{count}} files)`. Допустимы переменные `{{base}}`, `{{branch}}`, `{{date}}`, `{{datetime}}`, `{{count}}`. Пустое поле использует шаблон по умолчанию; шаблон ограничен 200 символами и не допускает неизвестные переменные или управляющие символы.

### Что происходит при первом подключении

IGoNotes может инициализировать `.git`, добавить или с подтверждением заменить origin, подготовить выбранную ветку и зафиксировать локальные файлы. Пустая локальная база может получить существующую удаленную историю; пустой remote — начальный локальный коммит. Когда история есть с обеих сторон, приложение сохраняет локальный снимок и объединяет его с удаленной веткой. Несвязанные истории либо история, связь которой проверка не смогла доказать, требуют подтверждения объединения; возможные конфликты разрешаются в интерфейсе.

Перед переключением или слиянием при наличии локального снимка, требующего защиты, создается резервная ссылка `refs/igonotes/backups/...`, сохраняющая этот коммит. Это локальный Git ref, а не отдельная копия каталога; автоматическая очистка таких ссылок не обещается. Уже существующие коммиты и история сохраняются, а не заменяются принудительной отправкой.

Если подключение завершилось ошибкой, прочитайте ее в карточке и проверьте актуальный статус и настройки: Git-настройки могли уже сохраниться до ошибки постановки операции в очередь. Исправьте причину и повторите подходящее действие по текущему состоянию базы.

### Ручная синхронизация и два устройства

В деталях индикатора Git нажмите `Синхронизировать Git`, а в карточке настроек — `Синхронизировать сейчас`. Перед ручным запросом интерфейс завершает ожидающие загрузки изображений и сохраняет текущую заметку. Ошибка сохранения блокирует запрос. Затем операция получает удаленные изменения, фиксирует локальные неигнорируемые изменения, выполняет обычное слияние и отправляет зафиксированный результат. При конфликте push не выполняется до явного разрешения.

Кнопка дерева `Обновить дерево (Синхронизировать с диском)` и `POST /api/sync` только сканируют файловую систему и обновляют метаданные дерева. Они не выполняют Git fetch, merge, commit или push; Git-синхронизация использует отдельный `/api/git/sync`.

Для работы на двух устройствах подключите отдельный локальный каталог на каждом к одному репозиторию и одной ветке. Синхронизируйте первое устройство после редактирования, затем второе — для получения изменений. Автосинхронизация может выполнять те же операции по расписанию, но одновременное изменение одного файла все равно может потребовать разрешения конфликта.

### Автосинхронизация, ошибки и возобновление

Автосинхронизация действует для всех настроенных баз, включая неактивные, пока приложение запущено. Следующий срок отсчитывается от последней попытки; операции выполняются последовательно. После запуска просроченные базы получают стартовые слоты с шагом пять секунд, а не все одновременно.

Первые четыре последовательные операционные ошибки допускают следующую попытку. Если подряд произошли **пять** таких ошибок, база получает статус `Приостановлено`, автоматические попытки прекращаются. Конфликт слияния и отказ валидации сами по себе не увеличивают этот счетчик. Удаление удаленной ветки или переписывание удаленной истории также могут немедленно приостановить синхронизацию. Пауза и счетчик сохраняются после перезапуска; восстановление сети само по себе не возобновляет работу.

При статусе `Ошибка` можно исправить причину и нажать обычную кнопку синхронизации. При паузе появляется `Git-синхронизация приостановлена` с причиной, счетчиком и временем последней попытки. Нажмите `Повторить и возобновить`: интерфейс сначала завершит загрузки и сохранит заметку, затем сбросит счетчик и поставит одну sync-операцию в очередь. Дождитесь результата; первая новая операционная ошибка начинает счетчик с 1. Кнопка `Открыть настройки Git` помогает исправить URL, ветку или режим. Обычная синхронизация паузу не снимает, а возобновление не обходит конфликт или необходимость переподключения.

### Как читать статус

| Надпись | Значение |
|:---|:---|
| `Git не настроен` | База работает локально без Git-интеграции приложения. |
| `Выполняется` | Подключение или синхронизация приняты в очередь либо выполняются. |
| `Синхронизировано` | Последняя операция успешна, сохраненный счетчик ahead равен нулю. |
| `Есть локальные изменения` | После успешной операции сохраненный ahead больше нуля. |
| `Ошибка` | Операция не удалась; после исправления причины возможна следующая попытка. |
| `Приостановлено` | Требуется явное возобновление. |
| `Конфликт` | Нужно разрешить конфликты или отменить слияние. |
| `Требуется переподключение` | Откройте Git-настройки и повторно подключите базу. |
| `Статус неизвестен` | Еще нет распознанного снимка статуса; дождитесь его обновления. |

В деталях `Впереди:` (`ahead`) — количество локальных коммитов сверх известной удаленной истории; `Позади:` (`behind`) — количество известных удаленных коммитов, которых нет локально. Также показаны этап и время последней успешной синхронизации. Это сохраненный снимок последней операции, а не непрерывный контроль remote или файлов: нулевые счетчики не доказывают отсутствие новых несохраненных правок или новых коммитов на другом устройстве.

### Разрешение конфликтов Git

В статусе `Конфликт` вместо обычного редактора открывается рабочая область `Конфликты Git`. Обычные изменения файлов этой базы и автосинхронизация блокируются. Выберите файл: `версия на этом устройстве` — локальная сторона слияния, `версия из репозитория` — полученная удаленная сторона. Приложение не выбирает победителя автоматически.

- **Текстовый конфликт:** `Оставить версию на этом устройстве`, `Оставить версию из репозитория` или `Объединить вручную` с редактированием итогового текста.
- **Бинарный конфликт:** выбрать одну сторону либо, если доступно, `Сохранить обе версии` в разные пути. Бинарные байты не объединяются текстовым редактором.
- **add/add:** обе стороны независимо создали файл в одном пути; выберите сторону, объедините текст либо сохраните обе версии в разные пути, если соответствующее действие доступно.
- **modify/delete:** одна сторона изменила файл, другая удалила. Доступны `Сохранить версию на этом устройстве` или `Сохранить версию из репозитория` для существующей стороны, ручное объединение текста либо `Удалить итоговый файл` с подтверждением.
- **rename/delete:** одна сторона переименовала файл, другая удалила исходный путь. Проверьте исходный и итоговый пути; сохраните существующую сторону, объедините текст или подтвердите удаление. Удаление относится ко всем путям этого логического конфликта.

Используйте только действия, показанные для выбранного конфликта: отсутствующую сторону нельзя выбрать как файл, а доступность ручного объединения или сохранения обеих версий зависит от снимка. При выборе обеих версий укажите разные свободные пути. Выбор стороны сохраняет ее исходные байты; ручное объединение сохраняет введенный итоговый текст.

Файлы можно разрешать по одному: частичные решения сохраняются в Git, а оставшиеся конфликты доступны после возврата или перезапуска. Когда неразрешенных файлов не осталось, нажмите `Завершить слияние` и дождитесь результата: создается merge commit, обновляется дерево и выполняется push. Ошибка отправки не означает, что разрешение нужно повторить или что merge commit исчез.

Чтобы отложить решение, выберите другую базу в левой панели и нажмите `Открыть базу`. Конфликт текущей базы остается незавершенным, ее автосинхронизация не продолжается; черновик конфликтной заметки сохраняется для возврата в текущей сессии. Несохраненный текст поля объединения не является долговечным разрешением — сначала сохраните решение файла.

Для отказа нажмите `Отменить слияние`, затем `Подтвердить отмену`. Неразрешенные изменения слияния отменяются, восстанавливается локальное состояние до слияния, включая заранее зафиксированные локальные изменения; push не выполняется. Исходные версии остаются в Git-истории, но несохраненный ручной результат не становится коммитом. После успешной отмены база приостановлена: для новой попытки используйте `Повторить и возобновить`.

### Ограничения

Не поддерживаются force-push, rebase, Git LFS, submodules, несколько remotes для одной базы, база как подкаталог monorepo и произвольный интервал автосинхронизации. Автоматического выбора решения конфликта и системных уведомлений нет.

## Настройки баз

Кнопка с шестеренкой открывает полноэкранные настройки. В разделе `Базы заметок` можно без перезапуска:

- создать новую базу или подключить существующий каталог;
- переименовать базу и изменить ее путь;
- переключить активную базу;
- забыть неактивную базу.

Изменение настроенного отображаемого имени или пути обновляет только конфигурацию. IGoNotes не перемещает каталог или файлы базы.

Перед переходом в настройки или переключением базы IGoNotes немедленно сохраняет текущую заметку и ожидающие загрузки. Если сохранение завершается ошибкой, переход блокируется, чтобы несохраненные изменения не потерялись.

Команда `Забыть` удаляет только запись базы из конфигурации и никогда не удаляет каталог или файлы. Нельзя забыть активную или единственную оставшуюся базу.

Настройки Git позволяют подключить репозиторий к базе и управлять синхронизацией без перезапуска.

`Отключить Git` с подтверждением очищает только Git-настройки приложения, статус и расписание. Выбор `Только вручную` отключает регулярные попытки, сохраняя подключение. Отключение Git и команда `Забыть` не удаляют `.git`, коммиты, refs, remote origin, каталог или пользовательские файлы и не удаляют удаленный репозиторий.

Смена пути в настройках не перемещает базу: перенесите каталог самостоятельно и укажите его новое расположение. Для настроенной Git-базы новый путь требует повторного подключения через Git-настройки (`Требуется переподключение`); прежнее расписание не переносится автоматически.

## Хранение данных

- Markdown-файлы остаются в каталогах баз, выбранных пользователем.
- Изображения базы хранятся в `<путь-базы>/assets/images/`.
- По умолчанию конфигурация хранится в `<os.UserConfigDir()>/igonotes/config.json`. В Linux это `$XDG_CONFIG_HOME/igonotes/config.json`, если переменная задана, иначе `~/.config/igonotes/config.json`. Флаг `--config <каталог>` переопределяет каталог, и файл хранится в `<каталог>/config.json`.
- Метаданные дерева хранятся в SQLite: `~/.igonotes/metadata.db`.

## Завершение работы

При обычном запуске в терминале нажмите `Ctrl+C`, чтобы остановить локальный сервер.

Пользовательский systemd-сервис не останавливается при закрытии терминала. Для временной остановки выполните `systemctl --user stop igonotes.service`, а для постоянного отключения и удаления — `igonotes service uninstall`.
